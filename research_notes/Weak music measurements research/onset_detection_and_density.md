# Onset detection and strike-density estimation for strummed electric guitar on separated stems (as of 2026-10)

Scope note: these notes cover onset detection functions (ODFs), peak-picking, guitar/strum-specific decision rules, metric-level (eighth vs sixteenth) estimation, drum-bleed handling and evaluation protocol. Numbers are quoted from primary sources where reachable. Where only an arXiv abstract page or a third-party summary was reachable, that is flagged. librosa defaults below were read directly from the installed `librosa 1.0.0` source in this project's `.venv` (`librosa/onset.py`, `librosa/util/utils.py`), because librosa.org's per-function documentation URLs returned 404 at the time of research.

---

## Key question 1: Which onset detection functions and peak-pickers do current libraries offer, and what F-measures do they report on guitar/polyphonic music? Which handle vibrato and distortion best?

### Takeaway
The librosa default is a mean-aggregated, log-mel spectral-flux envelope with a per-file min-max normalisation and a fixed `delta=0.07` offset over a 100 ms moving mean; SuperFlux (max-filtered flux, `max_size>1` in librosa, `superflux` in madmom) is the standard vibrato-robust hand-crafted ODF, and madmom's CNN onset detector is the strongest off-the-shelf learned detector (F1 ~0.93 on GuitarSet in an independent 2024 comparison versus ~0.92 for SuperFlux), but madmom's PyPI release is a 2018 source-only package with Python 2.7–3.7 classifiers and CC BY-NC-SA model weights. No reachable source evaluates onset detection on distorted electric guitar as a separate condition.

### Cited Findings

**librosa (installed 1.0.0; defaults read from source)**
- `librosa.onset.onset_detect(*, y=None, sr=22050, onset_envelope=None, hop_length=512, backtrack=False, energy=None, units='frames', normalize=True, sparse=True, **kwargs)`. With `normalize=True` (default) the envelope is shifted to min 0 and divided by its max (`onset_envelope - np.min(...)`, then `/= np.max(...) + tiny`), i.e. a whole-file min-max normalisation. — [librosa onset.py (installed 1.0.0 source; upstream)](https://github.com/librosa/librosa/blob/main/librosa/onset.py)
- Default peak-picking parameters set inside `onset_detect` are, in frames: `pre_max = 0.03*sr//hop_length` (30 ms), `post_max = 0.00*sr//hop_length + 1` (0 ms, i.e. 1 frame), `pre_avg = 0.10*sr//hop_length` (100 ms), `post_avg = 0.10*sr//hop_length + 1` (100 ms), `wait = 0.03*sr//hop_length` (30 ms), `delta = 0.07`. At sr=22050, hop=512 these evaluate to pre_max=1, post_max=1, pre_avg=4, post_avg=5, wait=1 frame (≈23 ms per frame), so the "30 ms" windows are actually a single frame. — [librosa onset.py](https://github.com/librosa/librosa/blob/main/librosa/onset.py)
- `librosa.util.peak_pick` selects frame n if (1) `x[n] == max(x[n-pre_max:n+post_max])`, (2) `x[n] >= mean(x[n-pre_avg:n+post_avg]) + delta`, (3) `n - previous_n > wait`. It cites Böck, Krebs and Schedl (ISMIR 2012) and the CPJKU `onset_detection/onset_program.py` reference implementation; a `method` argument selects `'greedy'` (earliest peak) or the Böck et al. variant. — [librosa util/utils.py](https://github.com/librosa/librosa/blob/main/librosa/util/utils.py)
- `librosa.onset.onset_strength_multi(*, y, sr=22050, S=None, n_fft=2048, hop_length=512, lag=1, max_size=1, ref=None, detrend=False, center=True, feature=None, aggregate=None, channels=None)`: default feature is `melspectrogram` with `fmax=sr/2`, converted with `power_to_db`; the reference spectrum is `scipy.ndimage.maximum_filter1d(S, max_size, axis=-2)` when `max_size>1` (this is the SuperFlux maximum filter), the envelope is `np.maximum(0, S[..., lag:] - ref[..., :-lag])`, then aggregated across frequency with `np.mean` by default (per `channels` slice if given), and optionally detrended with `lfilter([1,-1],[1,-0.99])`. `onset_strength` is the single-channel wrapper. — [librosa onset.py](https://github.com/librosa/librosa/blob/main/librosa/onset.py)
- The librosa gallery states that the SuperFlux method "is less susceptible to vibrato, and does not detect onset events at those points" compared with the default. — [librosa superflux example](https://librosa.org/librosa_gallery/auto_examples/plot_superflux.html)

**SuperFlux (Böck & Widmer, DAFx 2013) and reference parameters**
- Reference implementation defaults (`SuperFlux.py` argparse): `frame_size=2048`, `fps=200`, `bands=24` per octave, `fmin=30`, `fmax=17000` Hz, log compression `log(mul*X + add)` with `mul=1, add=1`, `max_bins=3`, diff-frame `ratio=0.5` (diff frames derived from window magnitude ratio), threshold `-t 1.1`, `pre_avg=0.15` s, `post_avg=0`, `pre_max=0.01` s, `post_max=0.05` s, `combine=0.03` s, `delay=0`. With local-group-delay weighting (`--lgd`, the ISMIR 2013 ComplexFlux variant) the recommended threshold drops to about 0.25. Licence: BSD-style header, copyright 2012–2014 Sebastian Böck. — [CPJKU/SuperFlux SuperFlux.py](https://github.com/CPJKU/SuperFlux/blob/master/SuperFlux.py)
- The SuperFlux paper's claim: a maximum filter tracking spectral trajectories reduces false positives "by up to 60%" on music with heavy vibrato "without missing any additional events". — [ajaysmurthy/SuperFlux README (fork of CPJKU/SuperFlux)](https://github.com/ajaysmurthy/SuperFlux); [PHENICX publication entry](https://phenicx.upf.edu/node/88.html)
- The companion ISMIR 2013 paper "Local Group Delay based Vibrato and Tremolo Suppression for Onset Detection" weights the spectral-flux differences by local group delay and reports up to 50% fewer false positives without additional misses (madmom's `complex_flux`). — [ISMIR 2013 paper PDF](https://archives.ismir.net/ismir2013/paper/000175.pdf)
- The SuperFlux ODF is also available as `essentia` `SuperFluxExtractor` (bands, max-filter, peak detection in one block). — [essentia SuperFluxExtractor](https://essentia.upf.edu/reference/std_SuperFluxExtractor.html)

### Inferences
- The project's reported symptom "raising sensitivity re-normalises the envelope and breaks other sections" follows directly from `normalize=True` plus a fixed `delta`: the per-file min-max scaling pins the envelope to the loudest single frame, so `delta=0.07` means "7% of the loudest onset in the whole stem above the local 200 ms mean". Loud choruses lift the max and depress quiet-verse peaks below threshold; lowering delta globally then admits ringing in the loud sections. Section-local scaling or a log/whitened ODF (see Q2) is the standard remedy.
- At sr=22050/hop=512 the default `wait` and `pre_max` are one frame (23 ms), so librosa's default will happily emit two peaks 46 ms apart; madmom's 30 ms `combine` and SuperFlux's 50 ms `post_max` are stricter. For a strum, which spreads string-by-string over tens of milliseconds, a `wait` of roughly 50–60 ms (2–3 frames at this hop, or a finer hop) is closer to published practice.
- SuperFlux-style max filtering (`max_size=3` in librosa with a 24-bands/octave log-frequency spectrogram or at least a mel spectrogram) is the cheapest change targeting the vibrato/bend false positives; it is a one-argument change in `onset_strength`.
- madmom's CNN is the best-scoring reachable detector on GuitarSet but is a poor fit for a pip-on-Windows torch environment: 2018 sdist, Cython build, NumPy alias breakage, and non-commercial model weights. The chirp-group-delay paper's timings (CNN ~1.1 s vs SuperFlux ~9 ms per track) also show the cost.

### Gaps
- No reachable paper evaluates onset detection on distorted electric guitar as a separate condition; the ISMIR 2015 playing-technique paper only warns that onset/offset detectors "may not be robust" to distortion and delay timbre changes ([ISMIR 2015 paper 119](https://ismir2015.uma.es/articles/119_Paper.pdf)).
- MIREX onset-detection leaderboard tables (nema.lis.illinois.edu / music-ir.org) could not be read: the summary pages are JavaScript-rendered and the hosts present mismatched TLS certificates; only the task definition page was readable (see Q6).
- Schlüter & Böck 2014 exact F-measure not confirmed (secondary sources put the CNN family around 0.90 on the Böck dataset; one replication dissertation reports 0.905 for its own variant).
- The Stowell & Plumbley 2007 ICMC PDF (QMUL / soundsoftware) was unreachable (connection refused / certificate error); the whitening formula was taken from Böck 2012's restatement instead.

## Key question 2: Theory of adaptive thresholding and peak picking; how to avoid the sensitivity trade-off; per-section/per-band normalisation; multi-band ODFs

### Takeaway
The standard peak-picker (Böck et al. 2012, used by librosa, madmom and SuperFlux) is "local max AND above moving-mean + δ AND minimum distance"; the volume-dependence problem is solved in the literature not by tuning δ but by making the ODF itself scale-invariant (log-magnitude spectral flux, adaptive whitening) and by keeping the threshold relative to a local moving average rather than a global max. Multi-band ODFs (librosa `onset_strength_multi` with `channels`, essentia `melflux`, SuperFlux's filterbank) are the documented route to onset functions that do not let one loud band mask others.

### Cited Findings
- Böck, Krebs, Schedl 2012, Section 2.3.4: frame n is an onset iff (1) `ODF(n) = max(ODF(n-w1 : n+w2))`, (2) `ODF(n) >= mean(ODF(n-w3 : n+w4)) + δ`, (3) `n - n_last_onset > w5`, with δ a fixed threshold and w1..w5 tunable. For online operation `w2 = w4 = 0`. Grid search found online optimum `w1 = 3`, `w3` between 4 and 12, `w5 = 3` frames; offline `w2 = 3`, `w4 = 1`, `w5 = 0` (frames at 100 fps, 23 ms frames). The paper explicitly does "not use the same thresholding parameters for all ODFs ... some of the ODFs have fewer peaks and hence need less averaging". — [Böck, Krebs, Schedl ISMIR 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- Same paper on thresholding theory: "Most methods use dynamic thresholding to take into account the loudness variations of a music piece. Mean, median or combinations are commonly used to filter the ODF." Picking all values above threshold (no local-max test) gives "a relatively high false positive rate because the threshold parameter must be set to a very low level". Whole-signal normalisation and smoothing "cannot be used in an online scenario", so a moving average normalises locally and the minimum-distance rule `w5` approximates smoothing. — [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- Volume robustness ("unnormalized penalty", attenuating inputs by 0 to -15 dB): the proposed log-filtered spectral flux was best at all attenuation levels except the RNN OnsetDetector.LL, which "is unaffected by any volume changes"; adaptive-whitening variants were third; the explanation given is that "computing the difference of two adjacent frames of the logarithmic spectrum has the effect of dividing the magnitude at frame n by that at frame n-1, resulting in the relative magnitude change rather than the absolute difference". Log compression `log(λ·X + 1)` with λ in 0.01–20 "was found to influence greatly the shape of the performance curve". — [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- Adaptive whitening (Stowell & Plumbley ICMC 2007) as restated in Böck 2012 eq. 2: per bin, `P(n,k) = max(|X(n,k)|, r, m·P(n-1,k))` and `|X(n,k)| ← |X(n,k)| / P(n,k)`, with r a floor and m a memory coefficient; Böck used "m = 10 and r = 0.005" for all ODFs (as printed). — [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- aubio's implementation of the same whitening: `relax_time` in seconds "between 20 and 500, defaults 250", `floor` "typically between 1.e-6 and .2, defaults to 1.e-4". The QMUL Vamp plugins describe the option as evening out "temporal and frequency variation in the signal, which can yield improved performance in onset detection, for example in audio with big variations in dynamics". — [aubio awhitening.h](https://aubio.org/doc/0.4.7/awhitening_8h.html); [soundsoftware publication record](https://code.soundsoftware.ac.uk/publications/8)
- librosa's peak_pick is a direct port of this rule with `delta` as δ and `wait` as w5; `onset_detect` applies it to a min-max normalised envelope with δ=0.07 and a ±100 ms mean (see Q1). — [librosa util/utils.py](https://github.com/librosa/librosa/blob/main/librosa/util/utils.py); [librosa onset.py](https://github.com/librosa/librosa/blob/main/librosa/onset.py)
- madmom's peak-picker applies `activations >= mov_avg + threshold` with pre/post-average windows that default to zero for the neural activations (pure fixed threshold 0.5 on a [0,1] probability), and the 2012 paper notes neural ODFs need only "a simple thresholding" because their peaks are sharp probabilities. — [madmom source](https://madmom.readthedocs.io/en/v0.16/_modules/madmom/features/onsets.html); [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- essentia's `Onsets` uses an adaptive threshold controlled by `alpha` (fraction of the local mean) over a `delay`-frame window after normalising and summing multiple detection functions. — [essentia Onsets](https://essentia.upf.edu/reference/std_Onsets.html)
- Multi-band ODF in librosa: `onset_strength_multi(..., channels=[slices])` computes the rectified log-mel difference per band and aggregates within each channel slice separately (`util.sync` with `aggregate=np.mean`), returning one envelope per band group. — [librosa onset.py](https://github.com/librosa/librosa/blob/main/librosa/onset.py)
- SuperFlux's filterbank: 24 bands/octave from 30 Hz to 17 kHz with log(1+X) compression before differencing; the ISMIR 2012 "SF log filtered" result attributed its high precision (88.3%) to "the filtering process reduc[ing] the spectrum to the most relevant components". — [CPJKU/SuperFlux](https://github.com/CPJKU/SuperFlux/blob/master/SuperFlux.py); [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- The chirp-group-delay paper proposes a valley-to-peak-distance picker: threshold `T = μ × (maximum valley-peak distance)` with μ "between 0.75 and 1", on a smoothed ODF; it says smoothing the ODF also improves legacy detectors. — [arXiv 2408.13734](https://arxiv.org/html/2408.13734)
- The ISMIR 2022 "Music Separation Enhancement" authors state they thresholded `onset_strength()` directly instead of using `onset_detect()` because matching onsets between two signals with the latter "was hard to correctly tune" (quoted via search summary of the PDF; the abstract page does not contain this passage). — [arXiv 2208.12387](https://arxiv.org/pdf/2208.12387)

### Inferences
- The literature's answer to "raising sensitivity breaks other passages" is to remove absolute-level dependence from the ODF before any threshold: (a) difference log-magnitudes (librosa already does `power_to_db`, but then min-max normalises the summed envelope, re-introducing file-level dependence), (b) whiten per bin with a slow decay (aubio/Böck), (c) use a moving-mean threshold whose δ is a fraction of local activity rather than a fraction of the global max. Switching `normalize=False` and passing `delta` in dB-flux units, or normalising the envelope per section/per rolling window (e.g. divide by a rolling 95th percentile over a few bars), are the project-level equivalents.
- Per-band ODFs give a direct handle on the "held tone ringing until the next hit" symptom on distorted stems: a strum re-excites all bands at once whereas sustain-plus-vibrato moves energy within a narrow band; requiring positive flux in ≥k of N band groups (or taking a product/geometric-mean across bands instead of the mean) is a generic rule with constants measurable across sections.
- Böck's own finding that different ODFs need different averaging windows implies the project should re-tune `pre_avg/post_avg/wait` whenever it swaps the ODF (e.g. after enabling `max_size=3`).

### Gaps
- No reachable source gives a canonical "per-section normalisation" recipe; the closest documented practices are the online moving-average threshold (Böck 2012) and adaptive whitening with a 20–500 s relaxation time (aubio). A rolling-percentile normaliser is an inference, not a cited method.
- The original Stowell & Plumbley paper's per-ODF F-measure gains with/without whitening were not retrievable.

## Key question 3: How do guitar-specific systems decide what is a strum onset versus a note onset or bleed?

### Takeaway
Current guitar systems treat "strum" as a learned event class rather than a thresholded flux peak: the ISMIR 2025 Klangio/KIT CRNN labels strums from a hand-mounted motion sensor and reaches F1 ≈ 98% on pickup audio where spectral flux manages ≈ 79%, and the Yousician 2025 MERT-based detector reaches F1 96.9 on separated stems versus 83.0 for a librosa peak-picking baseline; both use a 50 ms tolerance, a 0.5 probability threshold and a ±40 ms / 150 ms minimum-distance rule. Basic Pitch's onset head (Apache-2.0, pip-installable on Windows) is the only one of these that ships as a model, but it is a note-onset head with a 0.5 threshold and 120 ms minimum note length, trained on GuitarSet among other sets.

### Cited Findings
- Murgul, Schimper, Heizmann (ISMIR 2025, "Joint Transcription of Acoustic Guitar Strumming Directions and Chords"): a CRNN adapted from Kong et al.'s piano transcription model; input log-mel at 16 kHz, 2048 window, 160 hop, 229 bins from 30 Hz, 10 s clips; action branch of four conv blocks, FC 768, biGRU 256, 2-way up/down output, with a parallel 24-class major/minor chord branch; training target is a triangular onset-regression target (J=5), AdamW 1e-4, 20k steps; ±6 semitone pitch-shift augmentation. Ground-truth strum onsets came from spectral flux on the pickup signal guided by a metronome recording plan and checked manually; direction from the sign of the hand sensor's acceleration derivative. — [arXiv 2508.07973](https://arxiv.org/html/2508.07973v1)
- Results (50 ms, mir_eval): pickup audio F1-any: spectral flux 79.49%, SuperFlux 74.36%, complex-domain 79.32%, CRNN 97.60%; per-direction CRNN down 87.87% / up 84.90%; on microphone (phone) audio the CRNN trained on all data reached F1-any 92.75% (down 85.51%, up 79.02%), with no classic-ODF baseline reported on mic audio. Data: ~90 min real recordings plus ~4 h synthetic strumming; no code/model release or licence stated. — [arXiv 2508.07973](https://arxiv.org/html/2508.07973v1)
- The same group's earlier multimodal work used spectral flux for strum onsets and then "a pruning with a difference of 150 ms is performed to remove double hit detections", and states that "due to the very short time difference between the string hits, conventional note-based transcription methods cannot distinguish the direction of the strumming movement". — [KIT repository (Murgul et al.)](https://publikationen.bibliothek.kit.edu/1000183784/163349643); [KIT entry](https://publikationen.bibliothek.kit.edu/1000184108)
- Yousician, "Transcribing Rhythmic Patterns of the Guitar Track in Polyphonic Music" (arXiv Oct 2025): 931 proprietary recordings of 410 songs, 924 expert-identified rhythmic patterns; HTDemucs four-stem separation feeding the "other" stem (guitar separation judged weak, "barely above 0 dB SNR" for guitars); a MERT-v1-95M encoder with a 256-unit MLP head outputs per-frame strum probabilities, all 12 layers fine-tuned with a shift-tolerant weighted BCE; inference picks the highest-probability frame above 0.5 within a ±40 ms neighbourhood; augmentation with synthetic guitar stems and random transposition. — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)
- Yousician results (50 ms): fine-tuned on "other" stem F1 96.9 (P 96.7, R 97.6); on the 6-stem guitar stem 95.4; on the full mix 96.5; a librosa onset-peak baseline on isolated tracks 83.0. Separation artifacts "can be quite detrimental to onset detection"; the guitar stem scored lower partly because extra guitar parts in backing tracks bleed into it and "divert the model's attention". Example tracks: github.com/YousicianGit/rhythmic-pattern-transcription; the bar-line post-processing code is stated to be open-sourced but no licence is given. — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)
- Basic Pitch (Bittner et al., ICASSP 2022): fully convolutional, 16,782 parameters, CQT input at 3 bins/semitone with ~11 ms hop and harmonic stacking (7 harmonics + 1 sub-harmonic); three outputs (onset Yo, note Yn, multipitch Yp); onset loss class-balanced (negative weight 0.05, positive 0.95); training data includes GuitarSet (648 train / 72 test tracks) plus MAESTRO, Slakh, MedleyDB, iKala, Phenicx, Molina; post-processing peak-picks Yo, discards peaks below 0.5, grows notes forward through Yn, drops notes shorter than ~120 ms, and reports state-of-the-art note F on GuitarSet versus TENT and MI-AMT (tables not extractable). — [ar5iv 2203.09893](https://ar5iv.labs.arxiv.org/html/2203.09893)
- Basic Pitch package: `predict()` defaults `onset_threshold=0.5` ("minimum energy required for an onset to be considered present"), `frame_threshold=0.3`, `minimum_note_length=127.7` ms, `minimum_frequency=None`, `maximum_frequency=None`, `melodia_trick=True`. Licence Apache 2.0; Python 3.7–3.11; Windows supported with ONNX as the default runtime (`pip install basic-pitch`); TensorFlow/CoreML/TFLite optional. — [basic-pitch inference.py](https://raw.githubusercontent.com/spotify/basic-pitch/main/basic_pitch/inference.py); [spotify/basic-pitch README](https://github.com/spotify/basic-pitch)
- Klangio markets Guitar2Tabs for "strumming chords or fingerpicking"; a MusicRadar review notes it "performs better if you tell it what to listen for" and has trouble with downbeats; no technical description of its strum detection is published beyond the Murgul papers above. — [Klangio at MuseHub](https://www.musehub.com/partner/klangio); [MusicRadar review](https://www.musicradar.com/music-tech/klang-io-promises-to-turn-audio-into-notated-transcriptions-lead-sheets-and-guitar-tabs-but-does-it-actually-work-klang-io-transcription-studio-review)
- Chordify's published pipeline (ISMIR 2015 late-breaking) covers downbeat and chroma extraction with Sonic Annotator and HarmTrace chord selection; no strumming-pattern algorithm is documented. — [ISMIR 2015 LBD 42](https://www.ismir2015.uma.es/LBD/LBD42.pdf)
- TabCNN/GuitarSet context: the Yousician paper notes that note-tracking models "focus on individual note onsets and often struggle with the dense polyphony and rhythmic structure of strumming, where the emphasis lies on chord-level articulation". — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)

### Inferences
- Both 2025 strum systems converge on the same post-rule: probability > 0.5 and one event per ~40–150 ms window; the classic-ODF baselines they beat are run with their default peak-pickers, so part of the 15–20 point gap is the picker, not the ODF.
- The classic ODFs' systematic weakness on up-strums (spectral flux up 68.6% vs down 85.4%) matches the project's "weak strokes missed" symptom: up-strums excite fewer/thinner strings and produce smaller flux peaks, so any fixed δ tuned to down-strums drops them.
- Basic Pitch's onset head could serve as a second opinion without licence or install friction (Apache-2.0, ONNX on Windows), but its 120 ms minimum note length and note-level training mean it will report note onsets within a strum, not strums; it would need the same combine window as above.
- A pragmatic generic "strum vs note" test used implicitly by these systems is polyphony at the onset: a strum excites several strings within one combine window. On a pure-DSP pipeline this maps to counting bands with positive flux (Q2) or counting simultaneous pitch onsets from a multipitch head.

### Gaps
- No public code or weights for either 2025 strum detector; no MIDI/strum dataset with permissive licence located.
- Moises publishes nothing technical on strum/onset detection; nothing reachable describes how commercial chord apps derive strumming patterns.
- GuitarSet strum-level evaluations (as opposed to note-level) were not found; GuitarSet is annotated at note level.

## Key question 4: Estimating the metric level of a passage (eighths vs sixteenths) and avoiding double-density errors

### Takeaway
Tatum estimation in the literature is a whole-passage statistic: the tatum is "the time division that most highly coincides with all note onsets" (Gouyon/Bilmes), found from an inter-onset-interval histogram over all onset pairs or from the autocorrelation of the onset function, with integer-fraction candidates scored by a two-way-mismatch fit; the one current guitar-strum system (Yousician 2025) avoids per-onset grid choice entirely by Viterbi-decoding whole 1–2 bar patterns with transition costs that cut pattern changes from 27.8% to 15.4%.

### Cited Findings
- Gouyon (citing Bilmes): the tatum is not the shortest note but "the time division that most highly coincides with all note onsets"; a single sixteenth inside a run of eighths should not force a sixteenth grid; tatum selection seeks "an equilibrium between (1) how well a regular grid explains the onsets, and (2) how well the onsets explain this grid". — [auditory.org posting, Gouyon 2002](https://auditory.org/postings/2002/138.html)
- IOI-histogram method (Gouyon/Herre et al. patent): "The calculation of the IOI is not restricted to successive onsets, but to virtually all pairs of onsets in a temporal frame"; the histogram is low-pass smoothed; "tatum candidates are calculated as integer fractions of the most frequent IOI. The candidate is selected which predicts the harmonic structure of the IOI best according to the 2-way mismatch error function"; phase and period are then refined by correlating the onset vector with candidate grids. — [US patent 7,273,978](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7273978)
- Autocorrelation of an accent signal is "comparable to building an IOI histogram, without needing to discretize the signal into discrete onsets"; a periodicity window bounds candidate periods. — [US patent 7,612,275](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7612275)
- Audacity's MIR module first classifies the most likely tatum rate, then comb-filters the ODF autocorrelation for each bar division consistent with that tatum and picks the BPM with the highest combined score, using the tatum to narrow the beat rate. — [Audacity MIR namespace docs](https://doxy.audacityteam.org/namespace_m_i_r.html)
- Klapuri, Eronen, Astola, "Analysis of the meter of acoustic musical signals", IEEE TASLP 14(1), 2006 (earlier TUT report 1/2004) estimates tatum, tactus and measure pulses jointly; the hierarchy is "a measure pulse, a beat pulse and a tatum pulse, respectively referring to the longest to shortest". — [TUNI research portal record](https://researchportal.tuni.fi/en/publications/automatic-estimation-of-the-meter-of-acoustic-musical-signals/); [Nokia patent citing it](https://patents.justia.com/patent/9418643)
- Cemgil et al. on quantisation: "the usual approach taken is to assume a constant tempo throughout the piece, and to quantize each onset to the nearest grid point implied by the tempo and a suitable pre-specified minimum note duration", which ignores relations between neighbouring onsets; they model expressive timing deviations instead. — [Cemgil et al., MMM 2003](https://www.mcg.uva.nl/mmm-2003/papers/cdk-2/cdk-2.pdf)
- Yousician 2025 strum-pattern decoding: strum positions are normalised to 0–1 within a bar (bar lines from BeatThis, 70 ms tolerance; post-processing can delete bar lines or subdivide measures by small integer factors), then Viterbi-decoded into 1- or 2-measure patterns from an expert library of 924 patterns using a two-way-mismatch observation model, with transition costs c1, c2 (values not given); transition costs reduced pattern changes from 27.8% to 15.4% and time-signature discontinuities from 9.4% to 0.1%; pattern F1 96.8 with ground-truth bar lines, 95.3 with BeatThis bars, 94.7 with post-processed bars. — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)
- Augmentation in the same system includes synthetic guitar stems and transposition; the onset head's shift-tolerant loss and ±40 ms neighbourhood peak selection are the only density controls at onset level; grid level is a property of the decoded bar pattern, not of individual onsets. — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)

### Inferences
- The project's "voted into a row of hits" and "clicking 16ths when it's playing 8ths" failures are the per-onset-quantisation problem Cemgil and Gouyon describe. The cited remedy is to choose the grid for a passage from an IOI histogram over all onset pairs (not adjacent pairs only), take candidates at integer fractions of the dominant IOI, and score each by a two-way mismatch (how many grid points lack onsets AND how many onsets lack grid points). A sixteenth grid should win only when a substantial fraction of grid points are occupied; the patent/TWM formulation makes "many empty grid points" an explicit penalty, which is exactly the double-density guard.
- The autocorrelation route (librosa `autocorrelate` on the unnormalised onset envelope, or `tempogram`) needs no discrete onsets, so it is immune to the detector's threshold choice; comparing the autocorrelation at lag = beat/2 vs beat/4 relative to the beat lag is a per-section statistic with constants measurable across many sections.
- Yousician's result that pattern-level transition costs halve spurious pattern changes supports a hysteresis rule: do not switch a section's grid level unless the evidence margin exceeds a fixed band.

### Gaps
- The Klapuri 2006 paper text and its reported accuracies were not retrievable (IEEE paywall; the TUNI portal has no abstract).
- No reachable source gives a numeric occupancy threshold (fraction of grid points that must carry onsets) for choosing sixteenths over eighths; the TWM weights in the patent are not reproduced in the readable text.
- Octave-error-specific literature for tatum (as opposed to tempo) was not found.

## Key question 5: Handling drum bleed on a separated guitar stem

### Takeaway
No reachable work solves drum bleed on a separated guitar stem directly; the documented strategies are (a) choosing a stem/mix where the separator is strong (Yousician found the "other" stem beats the dedicated guitar stem), (b) harmonic/percussive separation so percussive and harmonic onsets are detected and merged separately, (c) spectral gating of upper frequencies before onset detection (DARC, no parameters given), and (d) onset-count sanity filters on stems. Cross-stem onset subtraction appears in no reachable paper.

### Cited Findings
- Yousician 2025: "separation artifacts can be quite detrimental to onset detection"; the HTDemucs six-stem guitar stem gave F1 95.4 vs 96.9 for the four-stem "other" stem, attributed to weaker guitar separation and bleed from other guitar parts. — [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)
- DARC (2026): separated drum audio was "quite poor, with frequent artifacts and non-drum instrument sounds in the background", attributed to separation "bleed and artifacts"; before onset detection (Beat-This) and transcription they "post-processed our audio by gating the upper frequencies to reduce noise and bleed", enhanced transients and applied light compression/normalisation; no cutoff or ratio parameters are given; onset/kick/snare F1 tolerances were 70 / 30 / 100 ms. — [arXiv 2601.02357](https://arxiv.org/html/2601.02357)
- Source-separation data augmentation for beat tracking discards separated drum stems with fewer than one prominent onset per second as a quality filter. — [arXiv 2106.08703](https://arxiv.org/pdf/2106.08703)
- HPSS (FitzGerald DAFx 2010): a median filter across time suppresses harmonic content, a median filter across frequency suppresses percussive content; percussive sounds appear as vertical lines, harmonic as horizontal. — [FitzGerald 2010 PDF](https://www.audiolabs-erlangen.com/resources/aps-w23/papers/2010_FitzGerald_HarmonicPercussiveSep_DAFx.pdf)
- An ISMIR 2013 rhythm study computed onsets "from both the percussive and the harmonic part as well as from the original audio" and found good results from tracking both. — [ISMIR 2013 paper 165](https://archives.ismir.net/ismir2013/paper/000165.pdf)
- A "percussiveness" detector independent of energy catches low-amplitude hi-hat hits that energy detectors miss, and notes that mallet/hammer instruments "may exhibit drum-like onsets prior to the stable harmonic regions of the note". — [Maynooth ELE-Bob9](https://mural.maynoothuniversity.ie/id/eprint/699/1/ELE-Bob9.pdf)
- Holzapfel et al.: onset accuracy "depends on the type of instruments as well as on the style of performance"; they examine phase (group delay), magnitude and pitch separately. — [Holzapfel IEEE onset paper](https://www.csd.uoc.gr/~hannover/MMILab-Andre_files/HolzapfelIEEEOnset.pdf)
- essentia documents that the phase-weighted `complex_phase` ODF "tends to over-detect percussive events", while `hfc` targets percussive events; i.e. the ODF choice itself biases towards or away from drum-like transients. — [essentia OnsetDetection](https://essentia.upf.edu/reference/std_OnsetDetection.html)
- Schlüter & Böck's CNN gains were attributed in part to "separate detectors for percussive and harmonic onsets". — [JKU record](https://research.jku.at/en/publications/improved-musical-onset-detection-with-convolutional-neural-networ/)
- A 2024 abstract (Foster & Dixon) tests whether onsets from separated jazz-quartet audio match onsets from the original stems and questions whether separation loss functions suit onset preservation; numbers not readable. — [FosterDixon DualOnset abstract](https://webspace.eecs.qmul.ac.uk/s.e.dixon/pub/2024/FosterDixon-DualOnset-Abstract.pdf)

### Inferences
- Since the pipeline already has a drum stem from the same separator, the cheapest generic bleed test is cross-stem: compute the same ODF on the drum stem and reject a guitar-stem onset whose drum-stem flux at the same frame exceeds the guitar-stem flux by a fixed ratio, or whose guitar-stem spectrum at the onset is dominated by the snare band with no harmonic (pitched) flux. This is an inference from the DARC/HPSS practice, not a published method.
- Running `librosa.decompose.hpss` on the guitar stem and requiring harmonic-component flux (not just percussive flux) at a candidate onset implements the "harmonic onset" half of the CNN/ISMIR 2013 split with no new dependency; a snare hit produces percussive flux with little harmonic flux, a strum produces both.
- Band-limited ODFs (Q2) double as bleed filters: a snare's energy sits in a broad noisy band around 150–250 Hz plus high-frequency hiss, whereas a strummed chord's flux is concentrated at the string fundamentals and low harmonics.

### Gaps
- No quantitative study of false onsets from drum bleed on guitar stems was found; the DARC fix has no parameters and was applied to drum stems, not guitar.
- No paper describing cross-stem onset subtraction was found.

## Key question 6: Evaluation protocol a small project could use

### Takeaway
Use `mir_eval.onset.f_measure` (default 50 ms window, best-case one-to-one matching, returns F, P, R) on ear-marked onsets per section, combine ground-truth onsets closer than 30 ms into one, count strictly (each annotation matched once), and report in addition the doubled-onset share of false positives and merged-onset share of false negatives as MIREX does; 25 ms is the stricter research window (madmom/Böck) but ±50 ms is what MIREX and all three 2024–2025 guitar papers used.

### Cited Findings
- `mir_eval.onset.f_measure(reference_onsets, estimated_onsets, window=0.05)` finds "the best-case matching between reference and estimated onset locations" via `util.match_events`; precision = matches / estimated, recall = matches / reference; returns `(0.0, 0.0, 0.0)` if either list is empty; `validate` warns on empty inputs and enforces `MAX_TIME = 30000.0` s; `evaluate()` returns an ordered dict with keys `F-measure`, `Precision`, `Recall`. — [mir_eval onset.py](https://raw.githubusercontent.com/mir-evaluation/mir_eval/main/mir_eval/onset.py)
- madmom's `OnsetEvaluation` defaults: `window=0.025` s and `combine=0.03` s (annotated onsets within 30 ms are merged). — [madmom evaluation.onsets](https://madmom.readthedocs.io/en/v0.16/_modules/madmom/evaluation/onsets.html)
- MIREX Audio Onset Detection: P = Ocd/(Ocd+Ofp), R = Ocd/(Ocd+Ofn), F = 2PR/(P+R); tolerance "from +/- 50 ms to less" with some files not annotatable better than ~50 ms; P and R averaged across multiple annotators; also reported: FP rate, doubled-onset rate within FP, merged-onset rate within FN; dataset 85 files, 14 minutes, 2–36 s each (30 solo drums, 30 solo monophonic pitched incl. 9 plucked strings, 10 solo polyphonic pitched, 15 complex mixes); submitters may sweep ten values of one parameter to trace a P-R curve. — [MIREX 2018 Audio Onset Detection task page](https://music-ir.org/mirex/wiki/2018:Audio_Onset_Detection)
- Böck 2012 protocol: ±25 ms "rather strict" window chosen over ±50 ms; strict counting ("two detections within the detection window of a single onset are counted as one true positive and one false positive"); annotated onsets within 30 ms combined at their mean; parameters chosen by grid search over the set; annotation done in two passes (slowed playback, then multi-resolution spectrogram refinement) marking "the earliest time point at which a sound is audible". — [Böck 2012](https://archives.ismir.net/ismir2012/paper/000049.pdf)
- The chirp-group-delay paper used ±50 ms "following common practice and the MIREX onset task" and reports per-dataset P/R/F; the ISMIR 2025 strum paper and Yousician both use 50 ms via mir_eval, Yousician using 70 ms for bar lines (matching BeatThis). — [arXiv 2408.13734](https://arxiv.org/html/2408.13734); [arXiv 2508.07973](https://arxiv.org/html/2508.07973v1); [arXiv 2510.05756](https://arxiv.org/html/2510.05756v1)
- A 2024 acoustic-guitar-technique paper argues many MIR datasets have loose onset timing and that tolerances as wide as ±50 ms are common, which matters when scoring with tight windows. — [ISMIR 2015 paper 119 / 2024 context via search](https://ismir2015.uma.es/articles/119_Paper.pdf)
- DARC's drum protocol: prompts with fewer than 2 detected onsets ignored; onset/kick/snare tolerances 70/30/100 ms. — [arXiv 2601.02357](https://arxiv.org/html/2601.02357)

### Inferences
- For a strum sheet the relevant unit is the grid cell, not the onset: after `mir_eval` onset F/P/R, a second score at grid level (hit/no-hit per eighth or sixteenth cell, per section) directly measures the "too many strikes" and "missed weak strokes" symptoms, and a density-ratio metric (predicted strikes per bar / annotated strikes per bar) exposes double-density errors that onset F-measure hides when extra onsets land near real ones.
- MIREX's doubled-onset and merged-onset rates are the right diagnostics for the project's two failure modes (ringing re-triggers vs merged fast sixteenths) and are trivial to compute from the match lists `mir_eval.util.match_events` returns.
- A per-section parameter sweep (MIREX's ten-value P-R curve) run across all ear-marked sections of all songs is the documented way to pick one global δ/wait inside the band where the curve is flat, satisfying the "constants set across many sections, never per song" constraint.

### Gaps
- MIREX leaderboard numbers for any year were unreadable (JS-rendered tables, TLS certificate mismatch on both hosts), so no official per-class F-measures for "solo plucked strings" or "complex mixtures" are included.
- No small-project evaluation write-up specific to strum sheets was found; the grid-level metric above is an inference.
