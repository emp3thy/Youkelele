# Note duration, offsets and damping (cut / ring / palm mute / staccato) from guitar audio, as of 2026

Scope: how note offsets and articulation are measured from guitar audio in the literature and in products, with a view to deciding whether a per-stroke "held vs cut" length can be measured on Demucs-style separated, distorted guitar stems. Project context (per-section ring flag from first-slot decay, withdrawn in 1.7 after cut/ring overlapped on every decay statistic) is taken as given.

## Key question 1: State of the art in note offset detection and reported offset F-measures for guitar versus piano

### Takeaway
Every mainstream transcription model (Onsets and Frames, Kong's high-resolution regression model, Basic Pitch, MT3, Omnizart) ends a note when a frame-activation output falls below a threshold, optionally helped by a dedicated offset head; offsets are universally the weakest output, with with-offset note F1 roughly 30 points below onset-only F1 on piano and 12 or more points below on GuitarSet, and most recent guitar papers do not report offset scores at all. GuitarSet's "ground-truth" offsets are themselves produced by an energy/spectral-flux heuristic, so a model that scores well against them is matching a decay rule, not a perceptual label.

### Cited Findings

Onsets and Frames (piano)
- Onsets and Frames evaluates two note metrics via mir_eval: "one requiring that onsets be within ±50ms of ground truth but ignoring offsets and one that also requires offsets resulting in note durations within 20% of the ground truth or within 50ms, whichever is greater." — [Hawthorne et al. 2018, arXiv 1710.11153](https://arxiv.org/abs/1710.11153)
- On the MAPS test set the model reports frame F1 78.30, note F1 82.29, note-with-offset F1 50.22 (P 51.32 / R 49.31), and note-with-offset-and-velocity F1 35.39; baselines Sigtia et al. 2016 scored 18.38 and Kelz et al. 2016 23.14 with offsets. — [Hawthorne et al. 2018](https://arxiv.org/abs/1710.11153)
- The paper motivates offsets perceptually: "a piece played with only onset information would either have to be entirely staccato or use some kind of heuristic to determine when to release notes. A high note-with-offset score will correspond to a transcription that sounds good." It also notes "accurate note identifications are further complicated by the way note energy decays after an onset." — [Hawthorne et al. 2018](https://arxiv.org/abs/1710.11153)
- For MAPS training labels, sustain-pedal control changes are translated into longer note durations: "If a note is active when sustain goes on, that note will be extended until either sustain goes off or the same note is played again." — [Hawthorne et al. 2018](https://arxiv.org/abs/1710.11153)
- The Magenta Onsets and Frames code is archived: the README says the model "is currently inactive and serves only as a supplement to the papers" and points to MT3; the only TensorFlow version mentioned is 1.15; checkpoints are provided for MAESTRO (piano) and E-GMD (drums). — [Magenta O&F README](https://github.com/magenta/magenta/blob/main/magenta/models/onsets_frames_transcription/README.md)

Kong et al. high-resolution regression (piano; the backbone of the newest guitar tools)
- On MAESTRO: Onsets and Frames (as cited) onset F1 94.80, onset+offset F1 79.67; the proposed onset+offset+velocity-conditioned model onset F1 96.72, onset+offset F1 82.47. — [Kong et al. 2020, arXiv 2010.01815](https://arxiv.org/abs/2010.01815)
- Offset decision rule (Algorithm 1): an offset is detected when either the offset-regression output exceeds a threshold and is a local maximum, or the frame-wise output falls below a frame threshold; all thresholds set to 0.3 on validation; scored with 50 ms tolerance and offset ratio 0.2. The paper's only remark on offset difficulty: "the waveform of audio recordings can be blurred, which will lead to the difficulty of offset detection." — [Kong et al. 2020](https://arxiv.org/abs/2010.01815)
- The inference package is `pip install piano_transcription_inference` (PyTorch; built with Python 3.7 / PyTorch 1.4.0, newer "should work but were not fully tested"); the README states Linux and macOS are supported and "Windows has not been tested"; mp3 input needs ffmpeg. — [PyPI piano-transcription-inference 0.0.5](https://pypi.org/project/piano-transcription-inference/0.0.5/)

Basic Pitch (instrument-agnostic; the one that is trivially installable on Windows)
- Note creation: onset candidates are peak-picked from the onset posteriorgram (likelihood ≥ 0.5); for each, the note is tracked "forward in time through Yn until the likelihood falls below a threshold τn for longer than an allowed tolerance (11 frames), then ending the note"; after onsets are used, extra notes are grown both forward and backward from any remaining frames above τn; "note events which are shorter than ≈ 120 ms are removed." — [Bittner et al. 2022, arXiv 2203.09893](https://arxiv.org/abs/2203.09893)
- The authors use the no-offset F-measure as the main metric "since the definition of offsets is less objective than onsets (e.g. due to reverberation, sustain pedal, annotation procedure)." — [Bittner et al. 2022](https://arxiv.org/abs/2203.09893)
- GuitarSet results (Table 2): NMP (Basic Pitch) frame Acc .70, Fno .79, F (with offsets) .56; MI-AMT baseline .43 / .59 / .27. MAESTRO: Fno .71, F .11. Model has 16,782 parameters. — [Bittner et al. 2022](https://arxiv.org/abs/2203.09893)
- Install: `pip install basic-pitch`; backends TensorFlow, CoreML, TFLite, ONNX, with ONNX the default runtime on Windows; Python 3.7–3.11; Apache-2.0 licence. — [spotify/basic-pitch README](https://github.com/spotify/basic-pitch)

MT3 (multi-instrument transformer)
- Onset+offset matching criterion: "|offset diff| ≤ max(0.2 · reference duration, 50 ms)". — [Gardner et al. 2022, arXiv 2111.03017](https://arxiv.org/abs/2111.03017)
- GuitarSet (Table 2): MT3 (mixture) frame F1 0.89, onset F1 0.90, onset+offset F1 0.78; MT3 single-dataset 0.82 / 0.83 / 0.65; Melodyne 0.62 / 0.28 / 0.13. MAESTRO: onset 0.95, onset+offset 0.80 (Hawthorne 2021 baseline 0.96 / 0.84). — [Gardner et al. 2022](https://arxiv.org/abs/2111.03017)
- Leave-GuitarSet-out (zero-shot): GuitarSet onset F1 drops from 0.90 to 0.32 and onset+offset+program F1 from 0.78 to 0.19. — [Gardner et al. 2022](https://arxiv.org/abs/2111.03017)
- MT3's tolerance sweep (10–500 ms) is used to diagnose label-timing errors in datasets: performance on well-timed datasets "tends to level off" as tolerance grows, while MusicNet/URMP keep improving. — [Gardner et al. 2022](https://arxiv.org/abs/2111.03017)
- MT3 "uses the T5X framework", provides Colab inference only, "we do not (easily) support training", Apache-2.0, "not an officially supported Google product." — [magenta/mt3](https://github.com/magenta/mt3)

Omnizart
- Omnizart's piano model is a U-Net outputting pitch-activation, onset and offset channels at 20 ms / 25-cent resolution; the paper gives no decoding thresholds; MAPS piano results are 72.50% frame F1 and 79.57% note F1 (pitch+onset), with no onset+offset score reported. Install `pip install omnizart` then `omnizart download-checkpoints`; MIT; README says it is "incompatible for ARM-based MacOS"; TensorFlow based. — [Wu et al. 2021, arXiv 2106.00497](https://arxiv.org/abs/2106.00497); [omnizart README](https://github.com/Music-and-Culture-Technology-Lab/omnizart)
- In a GuitarSet zero-shot comparison (onset-only F1, 50 ms): Omnizart 59.0, Basic Pitch 79.0, MT3 90.0, Lu et al. 91.1, Riley et al. 89.7. — [Riley, Edwards, Dixon 2024, arXiv 2402.15258](https://arxiv.org/abs/2402.15258)

Guitar-specific transcription and the offset gap
- Riley et al. 2024 (high-resolution guitar transcription via domain adaptation on Kong's model): results "evaluated on onsets only (no offsets or velocity)"; training data is "mostly 'clean' guitar sounds, without distortion or strong audio effects"; no code or model release is mentioned, aligned MIDI "available from the authors on request." — [Riley et al. 2024](https://arxiv.org/abs/2402.15258)
- TART (2026) fine-tunes Kong's CRNN (log-mel, 16 kHz, 100 fps, 229 bins; onset, offset, frame, velocity heads) on GAPS, Guitar-TECHS, Leduc and GOAT-DI; reports zero-shot F50 (onset ±50 ms, pitch ±50 cents) averaging 81.35% across GuitarSet, EGDB and noisy variants (Riley et al. 74.68%), again with no with-offset score; CC BY 4.0 paper, no repository named in the paper text I extracted. — [Gupta et al. 2026, arXiv 2609.11904](https://arxiv.org/abs/2609.11904)
- Kehling et al. (IDMT, DAFx 2014) define the offset of an isolated electric-guitar note as "the first frame after the envelope peak with less than 5 % of the peak magnitude" of the summed-harmonic envelope (i.e. −26 dB), smoothed with a 3-frame window; they use a 200 ms offset tolerance because "offset detection is a harder task (due to smoothly decreasing note envelopes)", versus 50 ms for onsets, and report offset P/R/F 0.98/0.98/0.98 on their IDMT-SMT-Guitar recordings. — [Kehling et al. 2014](https://www.dafx14.fau.de/papers/dafx14_christian_kehling_automatic_tablature_trans.pdf)
- GuitarSet offsets are not human-labelled: onsets are manually validated, then "Offsets are then automatically estimated" from an offset strength function Gb(t) = Nb(t)·(log E(t−l) − log E(t)) / E(t), combining negative-half-wave-rectified spectral flux and the log-RMS drop, with candidates within 30 ms of the onset discarded and "the first offset candidate in time" chosen. Manual onset validation also deliberately excludes "muted notes that shouldn't be included in the annotation." — [Xi et al. 2018, GuitarSet, ISMIR](https://ismir2018.ismir.net/doc/pdfs/188_Paper.pdf)
- mir_eval defaults: onset tolerance 0.05 s, pitch tolerance 50 cents, offset_ratio 0.2, offset_min_tolerance 0.05 s; "If offset_ratio is None, note offsets are ignored." MIREX differences (greedy matching, 2-decimal rounding, no 50 ms minimum) make mir_eval scores about 1–2% higher. — [mir_eval transcription docs](https://mir-eval.readthedocs.io/stable/api/transcription.html)

### Inferences
- Across piano and guitar, the piano "offset penalty" (onset F1 minus onset+offset F1) is about 14–32 points (O&F MAPS 82→50; MAESTRO 95→80/82); on GuitarSet it is 12 points for MT3 (0.90→0.78) and 23 points for Basic Pitch (0.79→0.56). The GuitarSet gap looks smaller than MAPS only because GuitarSet offsets are an algorithmic decay heuristic that the neural models can learn to mimic.
- No reviewed guitar paper after 2022 reports with-offset scores; the field has effectively given up scoring guitar offsets, consistent with Basic Pitch's stated reason (offsets are "less objective").
- Every model's offset is a threshold crossing of an activation that tracks energy decay. On a stem where a distorted stroke rings into the next hit, such models will place the offset at the next onset (Basic Pitch zeroes the frames used by a note, Kong truncates at repeated onsets), which is the same information the project already has from inter-onset intervals.
- Practical installability for a Windows pip/librosa/torch environment: Basic Pitch (ONNX, Apache-2.0) and `piano_transcription_inference` (torch, untested on Windows but pure Python) are the realistic candidates; MT3 (T5X/JAX, Colab) and Magenta O&F (TF 1.15, archived) are not; Omnizart is TensorFlow and has platform caveats.

### Gaps
- No source reports with-offset F-measure for any model on distorted or amp-rendered electric guitar; EGDB-PG reports onset and frame F1 only (see Q3).
- Model checkpoint sizes for MT3, O&F and Omnizart were not stated in the pages fetched (Basic Pitch is 16.8k parameters; Kong's model is ~15 M per TART's description of its backbone family; O&F ~18 M per Basic Pitch's description).
- The TART paper text did not expose a code URL; whether a pip-installable TART exists is unconfirmed.

## Key question 2: Palm-mute and staccato detection on electric guitar: datasets, features, accuracies

### Takeaway
Palm/right-hand muting as a timbre class is detectable: isolated-note classifiers reach 58–98% depending on dataset difficulty (Su et al. 2014: 68.7% F-score with 35% of mutes mis-called "normal" across seven tones including distortion; TART 2026: 97.9% F1 on a pooled multi-dataset test set). The cues named are a noisier attack and faster decay, and Kehling's IDMT system computes spectral-shape and envelope statistics separately for the attack and decay segments of each note. Nothing in the literature treats "stroke cut short versus let ring" as a classification target; staccato is defined in performance research purely by timing (sounding duration as a fraction of the inter-onset interval), which is an offset problem again.

### Cited Findings

Datasets
- IDMT-SMT-Guitar: about 4,700 note events on three guitars; plucking styles "finger-style, muted, and picked"; expression styles "normal, bending, slide, vibrato, harmonics, and dead-notes"; mono 44.1 kHz WAV. — [Fraunhofer IDMT guitar dataset page](https://www.idmt.fraunhofer.de/en/publications/datasets/guitar.html)
- Guitar-TECHS (2025): techniques alternate picking, palm mute, vibrato, harmonics, pinch harmonics, bendings; 138 palm-muted single notes per player; direct input plus miked amps (Orange CR-60, Yamaha, Orange CR-12 with SM57/AT2020/ECM8000) and two room mics; amplifiers at flat EQ, no statement on distortion; multitrack MIDI annotation at 9600 ticks/quarter; CC BY 4.0; total 5 h 12 min. — [Guitar-TECHS, arXiv 2501.03720](https://arxiv.org/html/2501.03720v1)
- Su, Yu and Yang 2014 dataset: 7 techniques (normal, muting, vibrato, pull-off, hammer-on, sliding, bending), 6,580 clips / 11,928 notes, recorded line-in on an ESP MII then rendered "to 7 different guitar tones, which involve different levels of distortion, reverb, delay and chorus" in Cubase; muting recorded "with only the last 3 strings because it is commonly used in rhythm guitar with low pitch." — [Su, Yu, Yang, ISMIR 2014](https://archives.ismir.net/ismir2014/paper/000213.pdf)
- The vocadito paper's two annotators were instructed to mark notes they would play on piano, and the GuitarSet protocol excludes muted notes from the note annotation (see Q1), so neither general dataset labels muting. — [GuitarSet](https://ismir2018.ismir.net/doc/pdfs/188_Paper.pdf)

Features and accuracies
- Su et al.: "muting has a 'noisier' attack and a faster decay comparing to normal"; muting is described as "Sounds muted (by right hand) to create great attenuation." Best feature set (sparse-coded log-cepstrum + group-delay + instantaneous-frequency deviation) gave overall F-score 71.7%; muting F-score 68.7% with 57.9% recall and 35.0% of mutes classified as normal; bending 89.4%, vibrato 86.9%. With a plain spectrogram the muting F-score was 56.1% (44.0% of mutes called normal). — [Su, Yu, Yang 2014](https://archives.ismir.net/ismir2014/paper/000213.pdf)
- Kehling et al. 2014: plucking style (finger / picked / muted) 93% mean normalised class accuracy, expression style 83%, string 82%; features include spectral centroid, roll-off, slope, spread, decrease, crest, flatness, inharmonicity factor, tristimulus, odd-to-even ratio and harmonic magnitude slope, each "condensed to 14 statistic values per note ... computed for the attack and the decay part of each note", plus note-level envelope features (temporal centroid, envelope fluctuation, envelope part length, temporal slope, attack-time deviation). — [Kehling et al. 2014](https://www.dafx14.fau.de/papers/dafx14_christian_kehling_automatic_tablature_trans.pdf)
- Abeßer et al. 2010 (bass guitar, 10 techniques, ~4,300 isolated notes): 93.25% for plucking styles and 95.61% for expression styles with domain-specific features. — [Abeßer, Lukashevich, Schuller, ICASSP 2010](https://doi.org/10.1109/ICASSP.2010.5495945)
- TART 2026 technique classifier: per-note 200 ms–3 s segments, 40 MFCC + 40 log-mel + 12 chroma at 23 ms hop, CNN-BiLSTM with ~160k parameters, nine classes including palm muting; palm muting precision 98.8%, recall 97.0%, F1 97.9% (1,952 test notes); macro F1 95.9%; trained on a pool of IDMT-SMT-Chords, Guitar-TECHS, AGPT, EG-IPT and Magcil with a 72/8/20 split in which "multiple microphone captures of the same performance never cross split boundaries." — [Gupta et al. 2026](https://arxiv.org/abs/2609.11904)
- TART's earlier version reports "distribution shift and overfitting when training on one dataset and testing on another" for technique classification. — [Gupta et al. 2025, arXiv 2510.02597](https://arxiv.org/pdf/2510.02597)
- Chen, Su, Yang 2015 (real-world distorted solos, 42 excerpts) detect only slide, vibrato, bend, hammer-on and pull-off from F0 sequence patterns; muting is not a target; they note existing "techniques for onset and offset detection may not" work in the presence "of sound effects such as distortion or delay." — [Chen et al., ISMIR 2015](https://ismir2015.uma.es/articles/119_Paper.pdf)
- Reboursière et al. 2012 detected palm muting, bends, hammer-ons, pull-offs, slides and harmonics, but from a hexaphonic piezo pickup (one signal per string). — [Reboursière et al., NIME 2012](https://nime.org/proc/reboursiere2012)
- Stefani's ExpressiveGuitar classifier includes a palm-mute class ("muting partially the strings with the palm of the pick hand") among percussive acoustic-guitar classes. — [ExpressiveGuitar-TechniqueClassifier](https://github.com/domenicostefani/ExpressiveGuitar-TechniqueClassifier)

Staccato / articulation
- In piano performance research, staccato "was realized by a micropause of about 60% of the inter-onset-interval (IOI)" and legato by key overlap whose relative size shrinks as the IOI grows. — [Bresin, KTH thesis summary](https://www.speech.kth.se/music/publications/thesisrb/)
- The key-overlap ratio (KOR) used in transcription evaluation is "the ratio between the time interval from the offset of the current note to the onset of the next note, and the time between the onsets of the two notes"; near-zero or negative values mean separation, positive values overlap. — [Towards Musically Informed Evaluation of Piano Transcription Models, arXiv 2406.08454](https://arxiv.org/pdf/2406.08454)
- The violin offset study found that for sharp-envelope techniques (pizzicato, spiccato) "energy-based method can be competitive", while spectral-flux detectors "typically take the beginning of decay as the offset position" and so fire too early. — [Liang, Su, Yang, Lin, ISMIR 2015](https://www.ismir2015.uma.es/articles/118_Paper.pdf)

### Inferences
- The palm-mute results are all on isolated, segmented notes or chords with ground-truth boundaries, mostly clean or lightly amped; the only distortion-inclusive result (Su 2014) shows muting is the class most confused with normal playing (35–44% leakage), which matches the project's finding that cut and ring overlap on decay statistics.
- Palm mute (a damped attack, continuous) and "cut after ringing" (a release event after a normal attack) are different signals: the former changes the attack spectrum and the whole decay rate, the latter only the tail. The literature supports the former as a per-stroke timbre class and gives no evidence for the latter as a classifiable event.
- The attack/decay-segmented feature statistics of Kehling (spectral flatness, decrease, inharmonicity over the decay segment) and Su's cepstral/phase features are the candidate feature families if the project ever tried a supervised palm-mute classifier; a nine-class 160k-parameter CNN-BiLSTM is cheap enough to retrain on project data in torch.
- Staccato is defined by timing, not timbre: sounding duration / IOI below roughly 0.4–0.5. Any staccato estimate therefore inherits the offset problem of Q1.

### Gaps
- No paper evaluates palm-mute or muting detection on full mixes or on source-separated stems; no paper reports technique-classification accuracy per tone (clean vs distorted) with numbers beyond Su's pooled result.
- The IDMT "muted" plucking style is not defined on the dataset page as palm mute specifically; Kehling's muted-row of the plucking-style confusion matrix did not survive PDF text extraction.
- No audio-based staccato/legato classifier for guitar was found; the only duration-ratio definitions come from piano/MIDI research.

## Key question 3: Decay measurements under distortion and compression; features that survive

### Takeaway
The literature confirms the project's observation indirectly rather than directly: high-gain tones degrade even onset and frame F1 (84.0 → 78.9 onset F1 low-gain to high-gain in EGDB-PG) and MT3 "struggles ... particularly in the later stages of the ADSR envelope" on amplified guitar, but no paper measures decay rate, offset accuracy or sustain under distortion. Effect-recognition work shows that the sustain segment of a distorted note is spectrally distinctive (541 spectral/cepstral/harmonic features from the sustain part classify effect chains at 99.2%), which is evidence that distortion rewrites the decay portion, not that any single decay feature survives it.

### Cited Findings
- EGDB-PG renders tablatures through 256 amp presets in three gain classes (96 low-gain, 64 crunch, 96 high-gain, Positive Grid BiasFX2), with an out-of-domain Neural DSP test set; the TIT model's onset F1 falls 84.0 → 81.6 → 78.9 and frame F1 68.4 → 67.6 → 64.5 from low-gain to crunch to high-gain; high-gain audio "present[s] greater transcription challenges due to their complex harmonics"; MT3 "struggles to capture key features of amplified guitar audio, particularly in the later stages of the ADSR envelope, where performance weakens"; the paper reports no with-offset metric and no clean-DI baseline. — [Towards Generalizability to Tone and Content Variations in the Transcription of Amplifier Rendered Electric Guitar Audio, arXiv 2504.07406](https://arxiv.org/html/2504.07406)
- EGFxSet: 138 notes × 5 pickup settings = 690 clean notes, each eight seconds apart to a 60 bpm metronome, played through 12 hardware effects (tube screamer, blues driver, RAT distortion, chorus, flanger, phaser, tape echo, digital delay, sweep echo, plate/hall/spring reverb); 8,970 files; CC BY 4.0 with a mirdata loader; the paper is a dataset description with no transcription or decay experiments. — [Pedroza, Meza, Roman, ISMIR 2022 LBD](https://ccrma.stanford.edu/~iran/papers/Pedroza_et_al_ISMIR_2022.pdf)
- Stein (DAFx 2010) detects cascaded guitar effects from "audio segments located in the sustain part of guitar tones" using "541 spectral, cepstral and harmonic features ... extracted from short time spectra", SVM with feature selection, 99.2% accuracy on ~50,000 tones for arbitrary combinations of six effects. — [DAFx paper archive](https://dafx.de/paper-archive/details/snbvFS1CWb6-HVRq1z6msA)
- IDMT-SMT-Audio-Effects: 55,044 mono 44.1 kHz single-note WAV files covering 11 effects including distortion and overdrive, on guitar and bass. — [Fraunhofer IDMT audio effects dataset](https://www.idmt.fraunhofer.de/en/publications/datasets/audio_effects.html)
- Schmitt and Schuller 2017 compare "a large variety of state-of-the-art acoustic features" (functionals and bag-of-audio-words) for effect recognition on over 50,000 guitar and bass samples with 10 effects; the page gives no per-feature ranking. — [Recognising guitar effects: which acoustic features really matter?](https://dl.gi.de/items/7bb35456-dee4-42f2-ad3c-f11ce33a0a07/full)
- Physical sustain of an electric guitar is quantified as the decay time to a 30 dB level drop at the neck pickup output; electric instruments sustain longer because the body does not radiate. — [Fleischer, ASA 137th meeting](https://acoustics.org/pressroom/httpdocs/137th/fleischer.html)
- Herbst 2017 on distorted rhythm guitar: experiments "point to frequency-related compression and the rough timbre due to the perception of partial and combination tones in the critical bandwidth and inharmonic string spectra"; it is a psychoacoustic study, not an envelope measurement. — [Herbst 2017, University of Huddersfield repository](https://eprints.hud.ac.uk/id/eprint/33249/)
- Chen et al. 2015 note that onset/offset detection methods "may not" be appropriate "in the presence of sound effects such as distortion or delay." — [Chen et al. 2015](https://ismir2015.uma.es/articles/119_Paper.pdf)
- Su et al. 2014 chose cepstral and phase-derivative features partly because "for distortions that involve a filtering effect, cepstral" features are less affected; their muting class still leaked 35% into normal across the seven tones. — [Su, Yu, Yang 2014](https://archives.ismir.net/ismir2014/paper/000213.pdf)
- Pitch-confidence-based offset detection outperformed energy and spectral-flux detectors on violin (overall F 0.654 vs 0.508 energy vs 0.492/0.489 spectral flux), because "the decaying phase exhibits similar signal characteristics as soft onsets when 'looking reversely' from the end of the signal"; energy-based detection was competitive only for sharp-envelope techniques. — [Liang et al. 2015](https://www.ismir2015.uma.es/articles/118_Paper.pdf)

### Inferences
- Clipping-style distortion acts as a compressor: amplitude over most of the ring is held near the clipping ceiling, so the dB-per-slot decay used in 1.6 measures the clipper's knee rather than the string, which is consistent with distorted stems "ringing until the next hit" and with cut/ring overlapping on every decay-share statistic.
- The features that the effect-recognition literature shows to be informative in the sustain of distorted notes are spectral-shape and harmonic-structure features (flatness, crest, inharmonicity, odd/even ratio), not amplitude slope; those are the features that would change when a string is damped (loss of high partials, rise of noise floor from the Demucs stem) even while the clipped amplitude is flat. This is an inference from Stein/Kehling/Su, not a tested result.
- The violin result (pitch confidence beats energy for soft decays) transfers as: on a separated stem, a per-stroke "is a pitched partial structure still present" measure (e.g. harmonic-to-noise ratio or pyin voicing probability over the slot) is a more promising cut-vs-ring feature than any level-drop statistic. Nothing found tests this on distorted guitar.
- Source separation adds its own time-varying noise floor, which will inflate any "fall to −X dB" measure on quiet tails; none of the reviewed papers evaluates offsets on separated stems.

### Gaps
- No study measures decay rate, T20/T30 or offset F-measure as a function of gain or compression on electric guitar; the question "which decay features survive distortion" is unanswered in the literature found.
- No study evaluates offset or articulation detection on source-separated (Demucs-style) stems.
- Per-partial decay and spectral-flatness-trajectory features for damping detection were not found in any guitar paper; they appear only inside large effect-recognition feature sets without per-feature results.

## Key question 4: How commercial tools decide printed note length; let-ring or staccato from audio

### Takeaway
Of the tools checked, only AnthemScore documents its rule, and it is the simplest possible one: "By default, each note ends where the next note starts," with per-note auto-stops that can be removed to fix an end. Soundslice does not transcribe audio at all (its "let ring" is a manual tab marking, drawn as a dashed line, with no playback effect); Moises exposes chords/tabs in-app with no notation export; Klangio/Guitar2Tabs and Melody Scanner publish no duration rule. No product was found that prints a let-ring or staccato marking derived from audio.

### Cited Findings
- AnthemScore: "By default, each note ends where the next note starts"; dragging a note's end fixes it; the note menu offers "Use auto-stops" (end at next note start) and "Remove auto-stops"; the docs do not say how stop times are derived from audio and do not mention staccato, sustain, let-ring or ties; MIDI export "Use musical (rounded) timing" snaps onsets and offsets to the grid; the smallest-note dropdown sets the quantisation grid. — [AnthemScore documentation](https://lunaverus.com/documentation)
- AnthemScore 5.0.0 (April 2024) release notes list "Options to prevent/allow note stop times being auto-set" and "More accurate note onset times." — [AnthemScore version history](https://www.lunaverus.com/versionHistory)
- Soundslice "let ring" is a tablature marking toggled per note in the editor's Tab section; "consecutive notes with let ring set are shown with one marking, a dashed line spanning all affected notes"; "It doesn't affect synthetic playback at this time"; the page says nothing about deriving it from audio. — [Soundslice help: let ring](https://soundslice.com/help/en/creating/tablature/121/let-ring)
- Soundslice's audio features align existing notation to a recording ("Sync with notation ... finds an optimal alignment"; older "Detect beats"); its AI work is optical music recognition of scanned scores, not audio transcription. — [Soundslice blog: auto-align audio with notation](https://www.soundslice.com/blog/290/new-auto-align-audio-with-notation/)
- Moises: AI chord detection with "instantly synced guitar tabs and chords" shown during playback, chord difficulty tiers (easy/medium/advanced); a competitor's comparison states Moises exports audio only and that chord results are in-app with no export planned (commercially interested source, unconfirmed). — [MusicTech on Moises tools](https://musictech.com/news/gear/moises-new-ai-tools/); [Songscription vs Moises](https://www.songscription.ai/blog/songscription-vs-moises)
- Klangio (Guitar2Tabs): users can set key, tempo, instruments and time signature to improve accuracy; a reviewer found rhythm detection "fails to identify swing, expressive timing and irregular rhythms"; the app listing warns of missed and wrong notes and that multi-instrument recordings give bad results; no duration or articulation rule is documented. — [MusicRadar review of Klang.io](https://www.musicradar.com/music-tech/klang-io-promises-to-turn-audio-into-notated-transcriptions-lead-sheets-and-guitar-tabs-but-does-it-actually-work-klang-io-transcription-studio-review); [Guitar2Tabs App Store listing](https://apps.apple.com/app/id1589660528)
- Melody Scanner: solo instruments only ("no bands or orchestras"); guitar supported; piano algorithm "up to 86% accurate"; free tier 40 bars, paid $9.99/month or $49.99/year with MIDI/MusicXML export; the site says nothing about how rhythm or durations are determined and nothing about articulation. — [melodyscanner.com](https://melodyscanner.com/)
- Melodyne, the commercial reference used as a baseline in MT3, scored onset+offset F1 0.13 on GuitarSet (onset F1 0.28) and 0.06 on MAESTRO, and in Onsets and Frames' MAPS table "Melodyne (decay mode)" scored 18.40 note-with-offset F1. — [Gardner et al. 2022](https://arxiv.org/abs/2111.03017); [Hawthorne et al. 2018](https://arxiv.org/abs/1710.11153)

### Inferences
- Commercial notation-from-audio products print duration as "until the next onset, quantised to the grid"; where they offer anything finer it is a manual edit. This is the same default the project reached by withdrawing the sustain line.
- The absence of any product-level let-ring/staccato from audio, despite strong commercial incentive (guitar tab apps), is weak but real evidence that the problem is not solved at consumer quality.

### Gaps
- Klangio's own help centre could not be reached (klangio.com/faq redirects to klang.io/faq which returned 404); no primary statement on its rhythm engine.
- Moises' help centre was not reachable via search; the "audio-only export" claim rests on a competitor's blog.
- Songscription (which claims audio-to-tab for acoustic guitar in standard tuning) was not examined in detail.

## Key question 5: Ground-truth protocol for labelling stroke length by ear and scoring a detector

### Takeaway
The literature's protocols are: (a) perceptual offset annotation step by step with Audacity at reduced speed, offset = "first perceived disappearance" of the pitch, with the next onset used as the offset for continuous notes (1–2 minutes per note); (b) scoring with mir_eval's offset window max(20% of reference duration, 50 ms), widened to 200 ms by IDMT for guitar, and clipped by an onset-aware window so a late offset cannot be credited past the next onset. Inter-annotator agreement on note boundaries is low even for vocals (F 0.64 with offsets vs 0.74 without), so a small project should label a binary per-stroke class with two listeners and report agreement before scoring any detector.

### Cited Findings
- Violin offset annotation procedure (Liang et al. 2015): normalise to −1 dB; transcribe identifiable pitches; listen repeatedly and zoom the waveform to place the onset at the start of the attack; take the offset as "the first perceived disappearance (i.e. below the audibility threshold) of that given pitch"; "For continuous notes, we simply find consequent note onset time and use it as the preceding note offset time", annotating independently only when there is clear overlap; replay at slower speed if unsure. A professional musician needed "1 to 2 minutes" per note including double-check; 63 clips, 1,226 offsets across six techniques. — [Liang, Su, Yang, Lin, ISMIR 2015](https://www.ismir2015.uma.es/articles/118_Paper.pdf)
- Same paper on why MIDI note-off is not usable as ground truth ("sustain pedal makes the synthesizer prolong the amplitude envelope even after the note-off message") and why spectrogram-only annotation is unreliable ("mismatch between the physical and perceptual offset"; masking; frequency-dependent audibility). — [Liang et al. 2015](https://www.ismir2015.uma.es/articles/118_Paper.pdf)
- Onset-aware evaluation window: the conventional window W = [−tol, +tol] around the annotated offset overlapped the next note's onset window "for more than 80% of notes in our dataset, when tolerance is set to 100ms"; they replace it with W' = [−tol, +post_tol] with post_tol = min(Δt + 50 ms, tol), where Δt is the distance to the succeeding onset, so that "the right margin of the tolerable window for offset would not exceed the right margin of the tolerable window for the succeeding onset." F-scores fell slightly under the stricter metric (pitch confidence 0.654 → 0.640). — [Liang et al. 2015](https://www.ismir2015.uma.es/articles/118_Paper.pdf)
- mir_eval / MIREX: offsets correct if within 20% of the reference duration or 50 ms, whichever larger; strict vs non-strict comparison flag; MIREX code omits the 50 ms minimum. — [mir_eval transcription docs](https://mir-eval.readthedocs.io/stable/api/transcription.html)
- IDMT used 200 ms offset tolerance versus 50 ms onset tolerance on isolated guitar notes "due to smoothly decreasing note envelopes." — [Kehling et al. 2014](https://www.dafx14.fau.de/papers/dafx14_christian_kehling_automatic_tablature_trans.pdf)
- vocadito (40 solo-vocal tracks, two independent annotators correcting Tony/pYIN note estimates): inter-annotator note F-score with offsets 0.64 (SD 0.13, range 0.34–0.88), ignoring offsets 0.74 (SD 0.09, range 0.57–0.94), frame accuracy about 0.80–0.83; "the notion of a note offset is ambiguous"; annotators were told to mark the notes they would play on a piano, which "mainly concerns how notes are segmented in time." — [Bittner et al., vocadito, arXiv 2110.05580](https://arxiv.org/abs/2110.05580)
- A 2026 onset-refinement paper treats 100 ms as "a reasonable approximation of typical human annotation error" for string and wind datasets whose "note-onset and offset annotations may be misaligned." — [Snapping Matters, arXiv 2606.11903](https://arxiv.org/pdf/2606.11903)
- MT3 uses a tolerance sweep (10–500 ms) to separate detector error from label timing error: well-labelled datasets plateau, noisy ones keep rising. — [Gardner et al. 2022](https://arxiv.org/abs/2111.03017)
- GuitarSet's own offsets are algorithmic (energy/flux novelty, first candidate after 30 ms), so GuitarSet cannot serve as perceptual cut/ring ground truth. — [GuitarSet](https://ismir2018.ismir.net/doc/pdfs/188_Paper.pdf)
- Articulation as a ratio: staccato micropause about 60% of the IOI; KOR = (next onset − this offset) / IOI. — [Bresin, KTH](https://www.speech.kth.se/music/publications/thesisrb/); [arXiv 2406.08454](https://arxiv.org/pdf/2406.08454)

### Inferences
- A workable small-project protocol, assembled from the above: (1) two listeners, independently, slowed-down playback of the separated stem with the mix available for context; (2) per stroke, a three-way label — rings into the next stroke / audibly stops before it / undecidable — rather than a timestamp, because timestamps on soft decays cost 1–2 minutes each and disagree; (3) optionally a timestamp only for "stops" strokes, with mir_eval's max(20% of IOI, 50 ms) window or IDMT's 200 ms, clipped by the onset-aware rule so nothing after the next onset counts; (4) report inter-listener agreement first; if agreement on the binary label is itself near chance on distorted stems, no detector can be validated, which would be a legitimate finding.
- Scoring per stroke is the honest unit; per-section aggregation should be reported as a derived statistic (fraction of strokes labelled "stops") so the reviewer can see whether a section flag is even well-defined (the 1.6 experience of medians sitting on the threshold suggests sections are mixed).
- Given vocadito's 0.64 with-offset agreement on clean solo vocals, expect lower agreement on distorted stems; a per-stroke feature would need to beat the inter-listener ceiling, not 100%.
- The KOR framing converts "held vs cut" into one number per stroke (sounding fraction of the IOI); the ear label can be defined as KOR-like thresholds (e.g. stops before 50% of the gap) to make it reproducible.

### Gaps
- No published inter-annotator agreement figures exist for guitar note offsets or for cut/ring judgments; vocadito (vocals) is the closest.
- No perceptual study was found giving the just-noticeable difference for note-release timing on guitar, which would be the principled tolerance.
- No standard exists for binary articulation labels (ring/cut) at the stroke level; the three-way label above is this note's proposal, not a cited protocol.
