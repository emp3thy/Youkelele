# Lyrics transcription and word-level lyrics-to-audio alignment for ukulele chord sheets (Python, Windows 11, consumer GPU) — notes compiled 2026-10-01

Scope note: the web-search budget was exhausted after the first batch of queries, so most findings below come from direct fetches of primary pages (GitHub READMEs, arXiv abstracts/HTML, PyPI pages, project docs). Where a primary page was unreachable (genius.com, developer.musixmatch.com, lrclib.net/docs rendered empty, alphatab.net lyrics page), that is flagged in Gaps and the fact is either sourced from a secondary page or omitted.

## KQ1. Automatic lyrics transcription (ALT) from the vocal stem — Whisper family, Parakeet, music-specific ALT, measured WER, effect of source separation

### Takeaway
Whisper large (v2/v3) run on a Demucs-separated vocal stem with sensible segmentation gives roughly 20–25 % WER on real pop/rock lyrics benchmarks (Jam-ALT / MUSDB-ALT), versus ~8 % on speech; a clean vocal stem (not a separated one) lowers it to ~14 %, and commercial systems (AudioShake) claim a 57 % relative WER reduction over Whisper v2. Non-lexical vocables and backing vocals are mostly deleted (>50 % deletion rate) regardless of separation, so expect to merge ASR output with reference lyrics rather than trust ASR alone.

### Cited Findings

Whisper models and runtime
- OpenAI Whisper model table (2026 README): tiny 39 M params / ~1 GB VRAM / ~10x; base 74 M / ~1 GB / ~7x; small 244 M / ~2 GB / ~4x; medium 769 M / ~5 GB / ~2x; large 1550 M / ~10 GB / 1x; turbo 809 M / ~6 GB / ~8x. Code and weights are MIT-licensed. The README states turbo "is an optimized version of large-v3" — [openai/whisper README](https://github.com/openai/whisper)
- Whisper turbo (large-v3-turbo) was announced 2024-10-01; it keeps the large-v3 encoder but has "only 4 decoder layers… down from the 32 in the large series", obtained by fine-tuning (not distillation) "for two more epochs" on the large-v3 multilingual transcription data (translation data excluded); it "performs similarly to large-v2" with "larger degradation on some languages like Thai and Cantonese". Available from openai-whisper 20240930; turbo is the CLI default. — [openai/whisper discussion #2363](https://github.com/openai/whisper/discussions/2363)
- faster-whisper (CTranslate2 reimplementation) is "up to 4 times faster than openai/whisper for the same accuracy while using less memory"; supports large-v3, distil-large-v3, turbo; has word-level timestamps, Silero-VAD filtering, `BatchedInferencePipeline`, INT8 quantisation; needs Python 3.9+, and for GPU "CUDA 12 with cuBLAS and cuDNN 9"; no FFmpeg needed (PyAV); MIT license. — [SYSTRAN/faster-whisper](https://github.com/SYSTRAN/faster-whisper)
- WhisperX "requires <8GB gpu memory for large-v2 with beam_size=5" with the faster-whisper backend; its CUDA guide gives Windows instructions ("For Windows users, download and install the CUDA toolkit 12.8"); BSD-2-Clause. — [m-bain/whisperX](https://github.com/m-bain/whisperX)
- Distil-Whisper distil-large-v3: 756 M params vs 1,550 M for large-v3; "6x faster"; short-form WER 9.7 % vs large-v3 8.4 % (speech); "Distil-Whisper is only available for English speech recognition"; supports `return_timestamps`; MIT. — [huggingface/distil-whisper](https://github.com/huggingface/distil-whisper)
- NVIDIA parakeet-tdt-0.6b-v3: 600 M-param multilingual (25 European languages) ASR with "accurate word-level and segment-level timestamps"; Open ASR Leaderboard avg WER 6.34 %, LibriSpeech test-clean 1.93 %; CC-BY-4.0; needs NeMo ≥2.4 (or HF Transformers); docs name Linux as the preferred OS, no Windows note; handles "audio up to 24 minutes long with full attention (on A100 80GB) or up to 3 hours with local attention"; nothing about singing/music is documented. — [nvidia/parakeet-tdt-0.6b-v3 model card](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3)

Measured WER on sung vocals
- Syed, Meresman Higgs, Cífka, Sandler (QMUL / AudioShake), "Exploiting Music Source Separation for Automatic Lyrics Transcription with Whisper", arXiv 2025-06-18. Setup: Whisper large-v2 via faster-whisper, beam 5; datasets Jam-ALT (79 songs, 283 min, EN/FR/ES/DE) and new MUSDB-ALT (39 songs, 166 min, with true vocal stems); separation with Hybrid Demucs `mdx` (7.97 dB SDR) and `mdx_extra` (8.76 dB SDR). Short-form (~20 s groups) WER: Jam-ALT mix 20.99 %, separated 21.08 %; MUSDB-ALT mix 23.59 %, separated 20.00 %, true vocal stem 14.19 %. Long-form with Whisper's native segmentation vs their RMS-VAD "Cut & Merge" (onset/offset 0.1, 1 s min silence, 30 s max segment): Jam-ALT mix 23.02 → 20.35 %, separated 22.87 → 20.72 %; MUSDB-ALT mix 25.82 → 22.72 %, separated 21.90 → 20.07 %, stem 17.51 → 14.98 %. Findings: ">50 % deletion rate for non-lexical vocables and backing vocals regardless of separation quality"; separation "artifacts… can trigger hallucinations (insertions ≥10 sequential words)"; RMS-VAD improves long-form WER 2.3–3.1 points. The paper claims state of the art for an open-source system on Jam-ALT long-form without training. — [arXiv 2506.15514](https://arxiv.org/html/2506.15514v1)
- LyricWhiz (ISMIR 2023, Zhuo et al.): Whisper-large with a language-specific prompt ("lyrics:"), 3–5 sampled runs per song, lines with no-speech probability >0.9 filtered, then GPT-4 chain-of-thought selection/correction. WER: Jamendo 24.25 % (vs 33.13 % W2V2-ALT, previous best 34.94 %); Hansen 7.85 % (vs 18.71 %); DSing 13.78 % (vs 12.99 % in-domain W2V2-ALT); MUSDB18 ~26–50 % by subset. Multilingual test WER: EN 21.86 %, FR 26.64 %, ES 22.54 %, IT 44.01 %, RU 39.18 %, DE 25.43 %. GPT-4 picked the ground-truth candidate 72.7 % of the time on Hansen. Released MulJam dataset: 6,031 songs, 6 languages, 182,429 lines, 381.9 h, CC-BY-NC-SA. — [arXiv 2306.17103v4](https://arxiv.org/html/2306.17103v4); code [zhuole1025/LyricWhiz](https://github.com/zhuole1025/LyricWhiz)
- Jam-ALT (Cífka et al.; ISMIR 2024 full paper; benchmark first released 2023) is built on JamendoLyrics with an industry-style annotation guide for punctuation, line breaks, letter case, background vocals and non-word sounds, and introduces metrics beyond WER (case-sensitive WER; P/R/F for punctuation, parentheses = backing vocals, line breaks, section breaks). — [arXiv 2311.13987](https://arxiv.org/abs/2311.13987); [AudioShake blog, 2024-09-05](https://www.audioshake.ai/post/lyrics-transcription-for-humans-revisiting-audioshakes-transcription-benchmark)
- AudioShake (2024-09-05) compared AudioShake v3, v1, Whisper v2, OWSM and LyricWhiz on Jam-ALT and reports a "57 % reduction in overall WER compared to Whisper v2" and 38 % v1→v3. (Commercial API; numbers are vendor-reported.) — [AudioShake blog](https://www.audioshake.ai/post/lyrics-transcription-for-humans-revisiting-audioshakes-transcription-benchmark)
- `alt-eval` (AudioShake, MIT, `pip install alt-eval`) implements the Jam-ALT metrics: WER on lyric-aware tokenisation (sacremoses), case-sensitive WER, and P/R/F for punctuation, parentheses, line breaks, section breaks; `compute_metrics(references, hypotheses)`. Useful for evaluating your own pipeline against LRCLIB reference lyrics. — [audioshake/alt-eval](https://github.com/audioshake/alt-eval)
- Whisper on Western classical singing (Schubert Winterreise): average WER 0.56 with unmodified Whisper, "varies greatly across songs and versions" (NLP4MusA 2024). — [aclanthology 2024.nlp4musa-1.3](https://aclanthology.org/2024.nlp4musa-1.3.pdf)
- Fine-tuning Whisper on singing (Greek, Interspeech 2026, submitted 2026-09-10): two-stage adaptation of Whisper large-v3 reaches 27.2 % WER, "a significant improvement over zero-shot baselines"; training data was built "using source separation and CTC forced alignment"; multitask learning helps mainly smaller models. — [arXiv 2609.11302](https://arxiv.org/abs/2609.11302)
- JamendoLyrics (the alignment/ALT benchmark): 79–80 songs, EN/FR/DE/ES (≈20 each), word-level start/end timestamps and line annotations; GitHub repo deprecated 2025-04-30 in favour of Hugging Face; per-song licenses are a mix of CC BY-NC-ND and CC BY-SA. — [f90/jamendolyrics](https://github.com/f90/jamendolyrics); [HF dataset](https://huggingface.co/datasets/jamendolyrics/jamendolyrics)
- DALI: large dataset with hierarchical note/word/line/paragraph lyric alignments; audio is NOT distributed — only YouTube links (some dead) via `get_audio()`; CC BY-NC-SA 4.0; cite Meseguer-Brocal et al., ISMIR 2018. — [gabolsgabs/DALI](https://github.com/gabolsgabs/DALI)
- Ready-made karaoke pipeline: `lyrics-transcriber` 0.81.0 (2025-12-08, MIT, Python 3.10–3.13) transcribes with AudioShake API (priority 1) or Whisper on RunPod (priority 2), fetches reference lyrics from Genius / Spotify / Musixmatch (RapidAPI) / local files, then corrects the transcript against the reference using "anchor/gap detection" and rule handlers (word count, syllables, punctuation…) with optional LLM help (Ollama/OpenRouter); outputs word-timed MidiCo LRC and ASS karaoke. Note: it relies on cloud services and on lyric sources whose terms are restrictive (see KQ2). — [lyrics-transcriber on PyPI](https://pypi.org/project/lyrics-transcriber/)

### Inferences
- For a hobby pipeline on a consumer GPU, faster-whisper large-v3 (or turbo for speed) on the Demucs/RoFormer vocal stem, with RMS/VAD-based ≤30 s segmentation and `language="en"`, is the evidence-backed open-source baseline; expect ~20 % WER on pop, i.e. roughly one wrong word in five. That is good enough for alignment anchors but not for a printable chord sheet, which is why fetching reference lyrics (KQ2) and then force-aligning (KQ3) is the better design.
- Separation helps most when the mix is dense (MUSDB-ALT improved 3.6 points) and barely at all on Jam-ALT; it can introduce hallucinations, so keep a hallucination guard (drop segments with ≥10 repeated/novel words, as the paper did).
- The LyricWhiz trick (several sampled Whisper runs + LLM selection) is reproducible with any LLM API and gave the biggest zero-shot gains on English (Jamendo 33 → 24 %).

### Gaps
- No per-system WER table for Jam-ALT could be retrieved (arXiv HTML versions 404'd; the website has no leaderboard). Only AudioShake's relative claim (57 % vs Whisper v2) is available.
- No published WER figures for Whisper large-v3, turbo, Distil-Whisper, Parakeet or Canary specifically on sung vocals were found; the 2025 QMUL paper used large-v2 only. Parakeet/Canary model cards do not mention singing.
- No measurements of RoFormer-separated vocals (vs Demucs) on ALT WER were found.
- Gupta et al. ICASSP 2020 numeric results (Kaldi polyphonic ALT) were not in the abstract page fetched.

## KQ2. Fetching known lyrics instead: Genius, Musixmatch, LRCLIB, lyrics.ovh, syncedlyrics, Spotify — what is legally usable in a hobby/open-source project

### Takeaway
LRCLIB is the only source found that is explicitly free, keyless, and returns line-synced LRC lyrics via a documented API (with a Python wrapper); Genius' API never returns lyric text and scraping its pages violates its terms; Musixmatch's free tier returns only 30 % previews and reserves full/synced lyrics for paid commercial plans; Spotify's lyrics require a logged-in cookie. LRCLIB serves user-contributed copyrighted lyrics, so "free API" is not the same as "licensed content"; for personal use on a song you already have the risk is low, but redistributing lyric text in an open-source repo is a copyright question regardless of source.

### Cited Findings

LRCLIB
- LRCLIB is "a completely free service for finding and contributing synchronized lyrics, with an easy-to-use and machine-friendly APIs"; server is Rust/Axum/SQLite, MIT-licensed. — [tranxuanthang/lrclib](https://github.com/tranxuanthang/lrclib)
- `GET /api/get` finds the best match for a track given title and artist; album name and duration (seconds) are recommended; "LRCLIB will attempt to provide lyrics only when the duration matches the record in the database, or at least with a difference of ±2 seconds". Response fields: id, name, trackName, artistName, albumName, duration, instrumental, plainLyrics, syncedLyrics (and lyricsfile on publish). — [lrclib.net/docs (as summarised in search results; page itself renders client-side)](https://lrclib.net/docs)
- Python wrapper `lrclib` (lrclibapi, v0.3.1): `LrcLibAPI(user_agent="my-app/0.0.1")`, `get_lyrics(track_name, artist_name, album_name, duration)`, `search_lyrics(track_name=…)`, `get_lyrics_by_id(id)`; returns `synced_lyrics` in `[MM:SS.xx] text` line format and `plain_lyrics`. — [lrclibapi docs](https://lrclibapi.readthedocs.io/en/latest/examples/fetch_lyrics.html)
- JS client docs confirm endpoints `/api/search` and `/api/get` with `track_name`, `artist_name`, `album_name`, `duration`, `id`, plus a `requestChallenge()` used for publishing. — [lrclib.js.org Client](https://lrclib.js.org/classes/Client.html)
- Third-party client note: "LRCLIB database contains a lot of questionable entries where track durations mismatch by a lot", and synced lyrics are plain line-level LRC ("Advanced LRC (split by words) is not supported"). — [slonopot/LRCLIBee](https://github.com/slonopot/LRCLIBee)
- Official desktop client LRCGET (Tauri, MIT, Windows/Linux/macOS) bulk-downloads LRC files from LRCLIB. — [tranxuanthang/lrcget](https://github.com/tranxuanthang/lrcget)

syncedlyrics
- `syncedlyrics` 1.0.1 (2024-07-28, MIT, Python ≥3.8; maintenance flagged "inactive" by libraries.io) searches Musixmatch, Lrclib, NetEase, Megalobiz, Genius (plain only), Lyricsify (broken: Cloudflare), Deezer (dead); supports `--synced-only/--plain-only` and "Enhanced (word-level karaoke) format" when a provider has it; `syncedlyrics.search("TRACK ARTIST")`. — [syncedlyrics on PyPI](https://pypi.org/project/syncedlyrics/); [libraries.io](https://libraries.io/pypi/syncedlyrics)

Genius
- The lyricsgenius docs: Genius "has legal agreements with music publishers" and withholds lyrics from the API; the library scrapes page HTML with Beautiful Soup, and "scraping the lyrics in this way violates Genius' terms of service" (personal use may not be enforced; "LyricsGenius is not responsible for your usage"). — [lyricsgenius: How it works](https://lyricsgenius.readthedocs.io/en/stable/how_it_works.html)

Google: Genius' breach-of-contract/scraping claims against Google (lyrics sourced via LyricFind) were held preempted by the Copyright Act. — [Frankfurt Kurnit summary](https://advertisinglaw.fkks.com/post/102hklg/how-does-that-song-go-again-lyrics-databases-claims-alleging-scraping-in-viol); [Bloomberg Law](https://news.bloomberglaw.com/ip-law/google-lyric-scraping-fight-with-genius-primed-for-supreme-court)

Musixmatch
- Free Developer plan: "up to 2,000 API calls per day", "only 30 % of each lyric's text", "intended for development and non-commercial use"; full and synced lyrics (track.subtitle.get, track.richsync.get) require a commercial licensed plan; paid tiers are "contact for pricing". (Secondary sources; developer.musixmatch.com itself was not fetchable.) — [publicapis.io Musixmatch](https://publicapis.io/musixmatch-api); [apis.io plans](https://plans.apis.io/plans/musixmatch/musixmatch-plans-pricing/)

Spotify
- `syrics` 0.1.2.5 (2025-10-12, GPL) downloads Spotify synced/unsynced lyrics to LRC but requires a logged-in `sp_dc` cookie (premium recommended). — [syrics on PyPI](https://pypi.org/project/syrics/)

### Inferences
- Recommended order for a hobby pipeline: (1) LRCLIB `/api/get` with YouTube title/artist/duration (duration from the downloaded audio; the ±2 s rule means use the actual audio length), (2) fall back to `/api/search` and pick by duration, (3) fall back to Whisper ALT. Always send a descriptive User-Agent (the Python wrapper requires it).
- Treat any fetched lyrics as copyrighted text: keep them local, do not commit them to a public repo, and do not redistribute generated chord sheets containing full lyrics publicly without a licence. Genius scraping and Musixmatch free-tier use for full lyrics are both terms violations; LRCLIB has no API terms barrier but offers no licence for the content either.
- LRCLIB's `syncedLyrics` are line-level only, so word-level timing must come from forced alignment (KQ3) even when LRCLIB hits.

- Could not fetch LRCLIB's own docs page (client-side rendered), so exact rate limits, the publish proof-of-work spec, and any stated data licence are unverified; lrclib.net/db-dumps also rendered empty (dump availability unconfirmed).
- Genius Terms of Service verbatim text could not be fetched (genius.com blocked); Musixmatch developer pages blocked; lyrics.ovh Apiary page rendered empty (endpoint/terms unverified).
- No authoritative source found on whether LRCLIB has ever received takedowns or on its legal status in the UK/EU.

## KQ3. Forced alignment of known lyrics to audio — WhisperX, MFA, MMS_FA / ctc-forced-aligner, stable-ts, lyrics-specific aligners (Stoller, Gupta/AutoLyrixAlign, Huang MTL, Durand contrastive)

### Takeaway
Speech CTC aligners (WhisperX's wav2vec2, torchaudio MMS_FA / ctc-forced-aligner, stable-ts `align()`) all run on Windows+CUDA and will align a known lyric text to the vocal stem word-by-word, but none is trained on singing and their accuracy on music is unmeasured in the sources found; the best published lyric aligners reach mean absolute error ≈0.35 s (Stoller 2019) and <0.2 s (Durand 2023, Spotify) on JamendoLyrics, with Huang 2022 MTL providing MIT-licensed checkpoints and Durand 2023 providing none. torchaudio's forced_align is deprecated in 2.8 and slated for removal in 2.9.

### Cited Findings

Speech-trained aligners
- WhisperX performs forced alignment with wav2vec2 phoneme models (`WAV2VEC2_ASR_BASE_960H` for English; default models for en/fr/de/es/it via torchaudio, more via Hugging Face). API: `model_a, metadata = whisperx.load_align_model(language_code, device)`; `whisperx.align(result["segments"], model_a, metadata, audio, device)` — the segments can be any text (you can pass reference lyrics split into segments with rough times). Limitation: "Transcript words which do not contain characters in the alignment models dictionary e.g. '2014.' or '£13.60' cannot be aligned". BSD-2-Clause. — [m-bain/whisperX](https://github.com/m-bain/whisperX)
- WhisperX paper (Interspeech 2023): Whisper's own timestamps underperform; word-segmentation precision/recall on Switchboard 93.2 %/65.4 % (WhisperX) vs 85.4 %/62.8 % (Whisper), AMI 84.1 %/60.3 % vs 78.9 %/52.1 %. Third-party guides quote "±50 ms" word accuracy vs "±500 ms" vanilla Whisper (not in the paper). — [Bain et al. 2023](https://www.isca-archive.org/interspeech_2023/bain23_interspeech.pdf); [vexascribe guide](https://vexascribe.com/whisperx)
- CrisperWhisper 2.0 (nyrahealth) reports 29.6 ms mean word-boundary error on TIMIT read speech vs 64.8 ms for WhisperX; timestamps come from "supervised cross-attention alignment"; inference code MIT but weights under a "Nyra Health Non-Commercial Research License" (commercial use needs a licence); models at huggingface.co/nyralabs. Paper Interspeech 2024 (arXiv 2024-08-29). — [nyrahealth/CrisperWhisper](https://github.com/nyrahealth/CrisperWhisper); [arXiv 2408.16589](https://arxiv.org/abs/2408.16589)
- torchaudio MMS_FA bundle (model trained on 23,000 h / 1,100+ languages) uses `torchaudio.functional.forced_align()` + `merge_tokens()`; text must be normalised (romanised via uroman, lowercase, strip non-letters except apostrophe); optional `<star>` token for unlabelled audio; returns word spans with scores. Deprecation: "Starting with version 2.8, TorchAudio is transitioning to maintenance mode… forced alignment APIs are deprecated in 2.8 and will be removed in 2.9." — [torchaudio MMS_FA tutorial](https://docs.pytorch.org/audio/stable/tutorials/forced_alignment_for_multilingual_data_tutorial.html)
- ctc-forced-aligner (MahmoudAshraf97): HF-based CTC alignment, default model MMS-300m-1130 (1,100+ languages; CC-BY-NC 4.0 — swap in a wav2vec2/HuBERT model for commercial use), code BSD-2; handles long audio with `window_size` 30 s and 2 s context overlap; uroman romanisation; outputs JSON word segments with start/end; requires FFmpeg; `pip install git+https://github.com/MahmoudAshraf97/ctc-forced-aligner.git`. — [ctc-forced-aligner](https://github.com/MahmoudAshraf97/ctc-forced-aligner)
- stable-ts (jianfch): word timestamps via cross-attention DTW; `align()` aligns a known plain-text transcript to audio at word level ("a faster alternative to full transcription when the text is already available"); supports faster-whisper via `load_faster_whisper()`; has voice isolation/denoise, 200–5000 Hz band-pass, Silero VAD, silence suppression; exports SRT/VTT/ASS/TSV/JSON. "Development on this repository is indefinitely paused" (read-only). — [jianfch/stable-ts](https://github.com/jianfch/stable-ts)
- whisper-timestamped (linto-ai): DTW on cross-attention weights; Silero/Auditok VAD; AGPL-3.0; "intended for experimental purposes and may significantly impact performance". — [linto-ai/whisper-timestamped](https://github.com/linto-ai/whisper-timestamped)
- Montreal Forced Aligner (Kaldi-based; v3.4 adds HF model formats): install `conda create -n aligner -c conda-forge montreal-forced-aligner -y` (pip also possible); Windows supported (paths like `//c/Users/...`); workflow `mfa model download acoustic english_us_arpa`, `mfa model download dictionary english_us_arpa`, corpus = wav + same-name .lab/.txt, `mfa validate …` (reports OOV words), `mfa align corpus dict model out` → TextGrids with word and phone tiers. — [MFA installation](https://montreal-forced-aligner.readthedocs.io/en/latest/installation.html); [MFA first steps](https://montreal-forced-aligner.readthedocs.io/en/latest/first_steps/index.html); [MFA home](https://montreal-forced-aligner.readthedocs.io/en/latest/)

Lyrics-specific aligners (trained on singing)
- Stoller, Durand, Ewert, ICASSP 2019: Wave-U-Net audio-to-character CTC model trained with weak line-level labels; "mean alignment error of 0.35 seconds" on the standard (Jamendo) dataset, "outperforms the state-of-the-art by an order of magnitude". — [arXiv 1902.06797](https://arxiv.org/abs/1902.06797)
- Gupta, Yılmaz, Li, ICASSP 2020 (NUS, Kaldi, music-informed polyphonic acoustic models) — the AutoLyrixAlign repo offers "word-level alignment of a given lyrics text to a given polyphonic music audio file", "outperformed all other systems in … MIREX 2019"; GPL-3 with separate commercial licensing; code in a Google Drive folder, 7 commits, no recent activity. — [AutoLyrixAlign](https://github.com/chitralekha18/AutoLyrixAlign); [arXiv 1909.10200](https://arxiv.org/abs/1909.10200)
- Huang, Benetos, Ewert, ICASSP 2022, "Improving Lyrics Alignment through Joint Pitch Detection": CTC acoustic model + multitask pitch/boundary; pretrained checkpoints in `/checkpoints`; MIT; author recommends the multilingual follow-up repo as better; evaluation via jamendolyrics scripts. — [jhuang448/LyricsAlignment-MTL](https://github.com/jhuang448/LyricsAlignment-MTL)
- Durand, Stoller, Ewert, ICASSP 2023 (Spotify), "Contrastive Learning-Based Audio to Lyrics Alignment for Multiple Languages": cross-modal embeddings instead of CTC, trainable from weak data, "average absolute error below 0.2 seconds on the standard Jamendo dataset", robust across languages though trained only on English; they released word-level alignments for JamendoLyrics Multi-Lang. — [arXiv 2306.07744](https://arxiv.org/abs/2306.07744)

### Inferences
- Practical Windows stack: faster-whisper/WhisperX for ASR, then align the LRCLIB (or corrected) lyric text to the vocal stem with WhisperX `align()` or ctc-forced-aligner; use LRCLIB's line timestamps to pre-segment the audio into ≤30 s windows (one line-group per window) before aligning, which sidesteps long-audio drift and makes repeated choruses unambiguous.
- Because torchaudio's aligner is being removed, prefer ctc-forced-aligner (pure HF) or WhisperX (which pins its own torchaudio) for longevity.
- Expect speech aligners to be worse than the ~0.2–0.35 s MAE of singing-trained models, especially on melisma and backing vocals; if you need better, the Huang 2022 MIT checkpoints are the only readily runnable singing-trained option found.

### Gaps
- No source measuring WhisperX / MMS_FA / MFA word-alignment error on sung vocals (all reported numbers are on speech corpora).
- Durand 2023 model weights: no release found. Huang 2022 numeric MAE on Jamendo not in README. Gupta 2020 MAE values not in abstract.
- "Jointist" (Cheuk et al. 2022) is a joint instrument-recognition/transcription model, not a lyrics aligner; no lyrics-alignment results found for it, so it is not covered here.
- MFA's behaviour on singing (long vowels, OOV slang) is undocumented.

## KQ4. Line/phrase segmentation, matching lyric lines to bars, repeated choruses and backing vocals

### Takeaway
No single tool does "lyric line → bar" matching; the workable recipe is: line boundaries from LRCLIB LRC timestamps (or Whisper segments), word onsets from forced alignment, bars/beats from a beat tracker, and section labels from a structure analyser such as `allin1` (verse/chorus/bridge with start/end times) — then snap each chord change to the nearest word onset within its bar. Backing vocals are mostly deleted by ASR and no open lead/backing separator was found in the main model zoo checked.

### Cited Findings
- Reference lyric lines come with line-level timestamps in LRC `[mm:ss.xx]` form from LRCLIB (KQ2). — [lrclibapi docs](https://lrclibapi.readthedocs.io/en/latest/examples/fetch_lyrics.html)
- The QMUL/AudioShake 2025 study found segmentation choice changes long-form WER by 2–3 points and recommends RMS-based VAD "Cut & Merge" (0.1 onset/offset thresholds, 1 s min silence, 30 s max) on the separated vocal; it also measured ">50 % deletion rate for non-lexical vocables and backing vocals regardless of separation quality". — [arXiv 2506.15514](https://arxiv.org/html/2506.15514v1)
- Jam-ALT's annotation guide marks background vocals with parentheses and scores line-break and section-break F1, i.e. industry lyric formatting treats backing vocals and section boundaries as explicit structure. — [arXiv 2311.13987](https://arxiv.org/abs/2311.13987); [alt-eval](https://github.com/audioshake/alt-eval)
- `allin1` (Kim & Nam, WASPAA 2023, MIT): `allin1.analyze('song.wav')` returns tempo, beats, downbeats, and functional segments with start/end and labels (intro, verse, chorus, bridge, outro…); depends on PyTorch, Demucs and NATTEN, which on Windows must be built from source (Ninja recommended). — [mir-aidj/all-in-one](https://github.com/mir-aidj/all-in-one)
- Sheet Sage uses `madmom` for beat/downbeat detection and emits audio-aligned MIDI melody + harmony (lead sheet). — [chrisdonahue/sheetsage](https://github.com/chrisdonahue/sheetsage)
- Repeated choruses: WhisperX's `align()` is applied per segment with the segment's time range, so passing each lyric line with its LRC start/end restricts the search to that window (prevents a repeated chorus line aligning to the wrong occurrence). — [m-bain/whisperX](https://github.com/m-bain/whisperX); ctc-forced-aligner also windows audio in 30 s chunks — [ctc-forced-aligner](https://github.com/MahmoudAshraf97/ctc-forced-aligner)
- Lead vs backing vocals: the Music-Source-Separation-Training pretrained list (checked 2026-10-01) lists top vocals/other models (BS-RoFormer viperx 10.87 dB, MelBand RoFormer KimberleyJensen 10.98 dB, BS PolarFormer 11.00 dB SDR on Multisong) but "no dedicated lead/backing vocal separation models". — [ZFTurbo pretrained_models.md](https://github.com/ZFTurbo/Music-Source-Separation-Training/blob/main/docs/pretrained_models.md)
- `lyrics-transcriber` already implements transcript-to-reference matching with "anchor/gap detection" (anchors = runs of words that match the reference; gaps resolved by rules such as word count/syllable count) — a reusable pattern for merging ASR words with LRCLIB lines. — [lyrics-transcriber](https://pypi.org/project/lyrics-transcriber/)

### Inferences
- Chord placement rule that follows from the data: for each chord-change time t (from the chord detector, snapped to a downbeat/beat), find the aligned word whose onset is nearest to t within ±half a beat and insert `[Chord]` before that syllable; if no word onset is within the window, emit the chord on its own (instrumental) or attach to the preceding word with a space, which is standard ChordPro practice.
- Use section labels from `allin1` to tag ChordPro `{start_of_chorus}` / `{start_of_verse}` and to de-duplicate repeated choruses (`{chorus}` directive) after confirming the aligned words of the repeats match.
- Backing vocals: since no open lead/backing separator was found and ASR drops them, treat parenthesised lines in reference lyrics as backing and either omit them or align them with a lower confidence threshold.

### Gaps
- No published method or evaluation found specifically for "lyric line ↔ bar" assignment for chord sheets; the recipe above is an inference.
- No open-source lead/backing vocal separator was verified (MVSep/UVR communities reportedly host such models but no primary page was fetched).
- Jam-ALT line-break F1 numbers for Whisper (how well Whisper's segment breaks coincide with lyric lines) were not retrievable.

## KQ5. Output formats — ChordPro, LRC / enhanced LRC, TTML, Ultimate-Guitar text — and Python/Node libraries

### Takeaway
ChordPro is a trivially writable text format (chords in `[ ]` immediately before the syllable, `{directives}` in braces) with a Perl reference implementation (ChordPro 6) that renders PDF; the only full-featured parser/formatter library found is ChordSheetJS (Node, GPL-2.0), which also reads and writes Ultimate-Guitar-style "chords over words"; no maintained Python ChordPro library was found (the `chordpro` PyPI package is removed). Enhanced LRC word timing uses inline `<mm:ss.xx>` tags.

### Cited Findings
- ChordPro syntax: "the lyrics of the song are interspersed with chords written between brackets [ and ]"; directives in braces such as `{title: …}`, `{start_of_chorus}` / `{end_of_chorus}`, `{comment: …}`; `#` lines are comments; recommended extension `.cho` (also .crd, .chopro, .chord, .pro); ChordPro 6 added markup/annotations; reference implementation is the Perl `chordpro` tool generating PDF. — [chordpro.org introduction](https://www.chordpro.org/chordpro/chordpro-introduction/)
- ChordSheetJS parses ChordPro, Ultimate Guitar chord sheets and "chords over words"; formatters: TextFormatter, HtmlTableFormatter, HtmlDivFormatter, ChordProFormatter, ChordsOverWordsFormatter, PdfFormatter (beta), MeasuredHtmlFormatter (beta); `npm install chordsheetjs`; works in Node and browser; GPL-2.0; 2,115 commits. — [martijnversluis/ChordSheetJS](https://github.com/martijnversluis/ChordSheetJS)
- PyPI `chordpro` 0.1.0 (2021-02-28) is the only release and "has been removed from PyPI". — [libraries.io chordpro](https://libraries.io/pypi/chordpro)
- LRC: `[mm:ss.xx]lyric` lines, ID tags `[ti:]`, `[ar:]`, `[al:]`, `[offset:]` (ms); Walaoke extension `M:/F:/D:` duet prefixes; "A2 Extension (Enhanced LRC)" adds word-level `<mm:ss.xx>` tags inside a line; sidecar naming song.lrc. — [Wikipedia LRC](https://en.wikipedia.org/wiki/LRC_(file_format))
- `lyrics-transcriber` writes word-timed "MidiCo LRC" and ASS karaoke subtitles plus CDG/MP4 — an existing Python reference for enhanced-LRC emission. — [lyrics-transcriber](https://pypi.org/project/lyrics-transcriber/)
- stable-ts exports word-level SRT/VTT/ASS/TSV/JSON directly from its alignment result. — [jianfch/stable-ts](https://github.com/jianfch/stable-ts)
- `syncedlyrics` can request "Enhanced (word-level karaoke) format" from providers that have it (in practice Musixmatch richsync). — [syncedlyrics](https://pypi.org/project/syncedlyrics/)

### Inferences
- Writing ChordPro from Python needs no library: for each line, insert `[C]` strings at the character offsets of the aligned words and emit `{title:}`, `{artist:}`, `{key:}`, `{start_of_chorus}` blocks. For Ultimate-Guitar "chords over lyrics" text, compute each chord's column from the word's character offset in the line and pad a chord line above it (ChordSheetJS's ChordsOverWordsFormatter does exactly this if you prefer calling Node via subprocess).
- Ukulele chord diagrams in ChordPro: the reference implementation supports instrument configs and `{define}` directives, but the fetched page did not show the ukulele specifics (see Gaps).

### Gaps
- ChordPro `{define:}`/ukulele instrument config details were not on the fetched page (chordpro.org has separate directive and config pages; not verified).
- TTML (Apple Music lyrics) syntax was not researched from a primary source; no fact recorded.
- No maintained Python ChordPro library confirmed (searches blocked by budget); `pychord` is a chord-name parser, not a ChordPro writer (not verified here).

## KQ6. Vocal melody for ukulele melody tab — syllable-to-note mapping, singing-voice transcription tools, rendering lyrics under tab (alphaTex, MusicXML/music21)

### Takeaway
Note-level singing transcription is available open-source via Omnizart `vocal` (MIT, Linux/macOS-only, Docker on Windows), VOCANO (MIT, PyTorch, old CUDA 10.1), Sheet Sage (lead-sheet melody+chords, CC BY-NC-SA models, Docker, 12 GB VRAM for Jukebox), Basic Pitch (Apache-2, Windows, instrument-agnostic) and RMVPE for F0 (Apache-2); map syllables to notes by hyphenating the aligned words with pyphen and assigning syllables to note onsets inside each word's aligned span; render with music21 `Note.lyric` (syllabic begin/middle/end/single → MusicXML) or alphaTab's `\lyrics` directive.

### Cited Findings
- Omnizart: `vocal` = "Transcribe note-level vocal melody", `vocal-contour` = frame-level F0; outputs MIDI; install `pip install omnizart` + `omnizart download-checkpoints`; supports Linux and Intel macOS, "Incompatible with ARM-based MacOS", Docker available; JOSS 2021; MIT. — [omnizart GitHub](https://github.com/Music-and-Culture-Technology-Lab/omnizart); [quick start](https://music-and-culture-technology-lab.github.io/omnizart-doc/quick-start.html)
- VOCANO (ISMIR 2021, MIT): vocal note transcription in polyphonic music via Patch-CNN pitch extraction + PyramidNet-110/ShakeDrop note segmentation (semi-supervised); PyTorch, CUDA 10.1, NVIDIA apex; evaluated on ISMIR2014 and CMedia; integrated into Omnizart. — [B05901022/VOCANO](https://github.com/B05901022/VOCANO)
- MIR-ST500 (Wang & Jang, ICASSP 2021): 500 pop songs with note annotations, audio via YouTube links; EfficientNet-b0 on/off/pitch frame classifier with pretrained model; uses Spleeter for vocal separation; note-level F-measure evaluation; author cautions a post-processing bug affects exact reproduction. — [york135/singing_transcription_ICASSP2021](https://github.com/york135/singing_transcription_ICASSP2021)
- RMVPE: "A Robust Model for Vocal Pitch Estimation in Polyphonic Music" (arXiv 2306.15412), PyTorch, Apache-2.0 — F0 only (no note segmentation). — [Dream-High/RMVPE](https://github.com/Dream-High/RMVPE)
- Basic Pitch (Spotify, ICASSP 2022, Apache-2.0): lightweight note transcription with pitch bends to MIDI; "works best on one instrument at a time"; `pip install basic-pitch`, Python 3.7–3.11, Windows/macOS/Ubuntu. — [spotify/basic-pitch](https://github.com/spotify/basic-pitch)
- Sheet Sage (ISMIR 2022, "Melody transcription via generative pre-training"): audio or YouTube URL → PDF lead sheet (LilyPond) + aligned MIDI melody and chords; trained on 50 h of HookTheory data; optional Jukebox features need 12 GB+ VRAM; madmom beats; Docker (~4 GB, +~10 GB for GPU parts); models CC BY-NC-SA 3.0 (non-commercial). — [chrisdonahue/sheetsage](https://github.com/chrisdonahue/sheetsage)
- Syllabification: `pyphen` 0.18.1 (2026-08-14; GPL2+/LGPL2.1+/MPL1.1; Python 3.10+) hyphenates with LibreOffice/Hunspell dictionaries, e.g. `Pyphen(lang='en_US').inserted('word')`. — [pyphen on PyPI](https://pypi.org/project/pyphen/)
- music21 `Lyric`: `text`, `number`, `identifier`, `syllabic` ∈ {single, begin, middle, end, composite}; setting `note.lyric = 'hel-'` auto-sets syllabic='begin' and text 'hel' (`rawText` keeps hyphens; `applyRaw=True` disables); `addLyric()` for multiple verses; MusicXML export maps number/identifier onto MusicXML's single `number` attribute. — [music21 note module](https://www.music21.org/music21docs/moduleReference/moduleNote.html)
- DALI provides note-level + word-level + line-level alignments (notes ↔ lyrics), i.e. ground truth for syllable-to-note mapping research (CC BY-NC-SA, audio via YouTube). — [gabolsgabs/DALI](https://github.com/gabolsgabs/DALI)
- Huang et al. 2022 showed joint pitch detection improves lyric alignment, evidence that melody notes and word boundaries are mutually informative. — [LyricsAlignment-MTL](https://github.com/jhuang448/LyricsAlignment-MTL)

### Inferences
- Windows-native path: RMVPE (F0) or Basic Pitch on the vocal stem for notes; Omnizart/VOCANO via Docker or WSL2. For a lead sheet with chords already there, Sheet Sage's Docker image is the most complete single tool but is non-commercial-licensed and heavy.
- Syllable-to-note mapping algorithm implied by the data: for each aligned word span [t0,t1], collect transcribed note onsets in the span; hyphenate the word with pyphen; if notes ≥ syllables assign syllables to the first N onsets and mark extra notes as melisma (MusicXML `extend`); if fewer notes than syllables, merge syllables. Then write music21 notes with `syllabic` set, export MusicXML, and generate uke tab (strings G C E A, music21/MuseScore or alphaTab).
- alphaTab can render a tab staff with lyrics from an alphaTex string, so the same syllable list can be emitted as an alphaTex `\lyrics` line for an HTML viewer (syntax unverified — see Gaps).

### Gaps
- alphaTex lyrics syntax: four fetch attempts (www.alphatab.net/docs/alphatex/lyrics, raw docs on GitHub `develop`/`main`) returned 404 or a landing page; the exact `\lyrics` directive rules (bar index, hyphen/underscore/plus conventions) are unverified.
- No benchmark numbers (COnPOff F-measure) were captured for Omnizart vocal, VOCANO or MIR-ST500 models from the fetched pages.
- Omnizart's Python/TensorFlow version pins were not on the fetched pages (known to be restrictive; unverified).
- No published tool found that performs automatic syllable-to-note lyric placement from audio; DALI is the only dataset with that mapping.
